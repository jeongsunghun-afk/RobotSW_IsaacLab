# s4_contact_safety

**S4 접촉 안전 — 조작 발이 접촉할 때 그 발로 체중이 넘어가는가.**

PLAN §5 의 **S4-G4 ①** 이 이 프로젝트의 유일한 hard constraint 다. Go2 자중 **147.3 N >
ISO/TS 15066 사람 손 접촉 한계 140 N** 이므로, 하중 전이가 일어나면 접촉력이 작아도 위험하다.
그래서 힘 크기가 아니라 **"CoM 이 지지 발 3개의 삼각형 안에 남는가"** 를 본다.

## 비교 대상

| 태그 | 체크포인트 | 비고 |
|---|---|---|
| `s1_first` | `2026-07-27_18-44-01/model_10600.pt` | S1 첫 산출. jvel 필터 없이 학습 |
| `jtr40_jvf` | `2026-07-31_09-31-33_jtr40_jvf/model_21597.pt` | 떨림 수정 당시 채택본 (2026-08-05 해제) |
| `drift50` | `2026-07-31_16-49-41_drift50/model_25596.pt` | base 표류 억제본 |

평가: `--mode contact --contact_press_z 0.00`, 1024 env × 2 seed. 접촉면은 지면이다 —
명령 박스 하단이면 조작 발이 실제로 닿으므로 별도 물체 없이 학습 분포 안에서 접촉이 성립한다.

|---|---:|---:|---:|
| 접촉 성립 | 62.7% | 100.0% | 100.0% |
| **① 위반 시행** | **0.00%** | 0.05% | **19.19%** |
| 지지 여유 중앙 | +84.6 mm | +53.0 mm | +34.2 mm |
| **지지 여유 5p** | **+67.6 mm** | +28.0 mm | **−26.7 mm** |
| ② 접촉 속도 중앙 | 0.030 | 0.052 | 0.052 m/s |
| ② 절대한계(1.3) 초과 | 0.00% | 0.10% | 0.00% |
| **정상상태 하중** | **19.6 N (자중 13.3%)** | 36.1 N (24.5%) | **45.2 N (30.7%)** |
| S4-G2' 순 감속 | **93.0%** | 77.8% | 62.6% |

**다리별 위반율** — `drift50`: FL **72.3%** · FR 4.5% · RL 0.0% · RR 0.0%.
다른 두 정책은 전 다리 0%.

⚠ **`s1_first` 의 0.00% 는 커버하는 상황이 좁다.** 위반율의 분모는 접촉이 성립한 시행뿐이므로
(`report_contact:864`, `a = touched`) 62.7% 라는 낮은 접촉률이 비율을 희석하지는 **않는다.**
그러나 다리별 접촉률이 FL 99.6% · FR 100% · **RL 15.0% · RR 36.1%** 라, `s1_first` 는 뒷발을
바닥까지 내리는 일 자체가 드물다. 앞다리끼리는 접촉률이 같으므로(FL 99.6% vs 100%)
**FL 0.0% vs 72.3% 비교는 공정하고, 판정도 여기에 걸려 있다.** `jtr40_jvf` ↔ `drift50` 은
양쪽 다 접촉률 100% 라 무조건 공정하다.

## 판정 — `base_drift` 페널티가 접촉 안전을 무너뜨렸다

위반 0.05% → **19.19%**. 기전은 명확하다: **앞발을 지면에 대려면 몸통이 뒤로 물러나야 CoM 이
뒷 3발 삼각형 안에 남는다.** `base_drift` 가 그 이동을 막으니 CoM 이 삼각형 밖에 남고 조작
발로 체중이 넘어간다. FL 에 72% 집중된 것이 그 서명이다.

`drift50` 채택 결정의 전제가 깨졌다. 표류 5.55 → 3.01 cm 의 이득으로 이것을 상쇄할 수 없다 —
안전은 trade 대상이 아니라 constraint 다.

⚠ **사전 리스크 예측이 절반만 맞았다.** counterbalance 억제의 대가로 "커버리지"와 "push" 를
지목했고 둘 다 깨지지 않아 안심했는데, 실제 대가는 보지 않은 세 번째 축에서 나왔다.
**규제를 추가할 때 확인할 축을 미리 열거하는 것으로는 부족하다** — 열거에서 빠진 축이 문제였다.

## 정상상태 하중이 단조 증가한다

13.3% → 24.5% → 30.7%. fine-tune 을 거듭할수록 조작 발에 체중을 더 싣는다. 정확도가 단조
하락한 것(`hold` 오차 12.46 → 15.60 → 19.75 mm)과 같은 방향이다.

**S1 첫 산출이 정확도에서 최고**인 것은 그대로다(12.46 mm). 접촉 안전에서도 모든 지표가
최고지만, 위 caveat 대로 **뒷다리 접촉이 드물어 검증 범위가 좁다** — "두 축 모두 최고"
대신 "정확도 최고, 접촉 안전은 측정된 범위에서 최고"가 정확한 표현이다.

## 지표 정정 3건 — 첫 측정은 판정에 쓸 수 없었다

| 지표 | 처음 | 정정 | 영향 |
|---|---|---|---|
| ② 판정 기준 | "0.5 m/s 초과 0건" | 절대 1.3 초과 0건 = PASS, 권고 0.5 는 95p 로 별도 | PLAN 문구보다 엄격했다 |
| ③ peak force | 40 / 140 N 절대 PASS/FAIL | **절대 판정 제거**, **정상상태 힘** 신설 | PLAN 이 명시적으로 금지한 것을 했다. peak 최대 1752 N 은 물리력이 아니라 충돌 트랜지언트 |
| S4-G2' | "10 step 전부 비증가" | **순 감소**(v 접촉 < v 0.2 s 전) | 1.6% → 62.6% 로 판정이 뒤집혔다. 극값 지표였다 |

`foot_amp` 를 `(max−min)/2` 로 쟀다가 틀린 것과 같은 계열의 실수가 두 번 더 나왔다.
**임계 초과율·극값은 지표로 쓰기 전에 잡음 민감도를 먼저 볼 것.**

## 잡은 버그 2건

- **`patch_command` 는 resample 함수만 설치한다.** `_cmd_timer` 가 1e6 으로 고정돼 있어
  에피소드 중 목표 변경이 적용되지 않았고, 첫 sweep 3조건이 **비트 단위로 같은 결과**를 냈다.
  목표를 직접 쓰도록 고쳤고 `contact_press_z` 를 결과 JSON 에 기록해 재발을 눈으로 잡게 했다.
- **GPU 경합 시 RTX 렌더가 조용히 빈 프레임을 낸다.** 350 프레임이 전부 균일 회색으로 나왔고
  예외는 없었다. 판별은 로그의 `Skipping NVIDIA graphics device` 개수가 아니라(그 경고는 정상
  케이스에도 나온다) **프레임 std 가 0 인지**로 한다. 한가한 GPU 로 옮기면 해결된다.

## 남은 것

- `drift50` 철회 여부 결정. 몸통 억제 자체는 옳은 방향이므로, **접촉 중에만 데드존을 넓히거나**
  `Metric/support_violation_rate` 를 직접 페널티에 넣는 형태로 재시도할 수 있다.
- S4-G1' 은 지면이 아니라 **전용 정적 물체**로 다시 재야 한다 (S5-B 물건 터치와 공유).
- 접촉 계측은 학습 중에도 상시 켜져 있다 (`Metric/support_violation_rate`,
  `manip_contact_rate`, `manip_load_peak_N`).
