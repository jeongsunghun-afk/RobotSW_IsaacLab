# velscale sweep 50k — 대칭 축과 배포(estimator) 조건

`leg_imitation_tracking` (17-DOF) 의 `vel_err_scale` sweep 이 50000 iter 를 완주해, 24k 시점에
유보했던 판정을 확정한다. 이 문서는 **다른 세션이 만든 GT 판정을 보완**한다 — 램프 자체는
재실행하지 않았다.

## BLUF

- **`vel_err_scale=1.5` 가 세 축 모두에서 최고다.** 고속 추종(steady 96.6%), 정지 출발(start 71.8%),
  자세 대칭(skew 0.123) 이 전부 1등이다. 24k 때 남겨 둔 대안 가설 — "s=1.5 의 낮은 symmetry loss 는
  고속을 포기한 결과일 수 있다" — 은 **반증됐다**.
- **`vel_err_scale=1.0` 은 기준보다 나쁘다.** 학습측 symmetry loss 가 ~32k 에서 기준을 추월해
  45k 에 0.630(기준 0.325) 까지 가고, 램프에서 **8회 중 4회가 cmd 4.0 에서 넘어진다**(기준 0/8).
- 24k 시점의 "s=1.0 이 기준보다 대칭적으로 보인다" 는 **관측 시점의 함정**이었다. 그때 값(0.136)은
  최종의 1/5 이었다.
- **배포(estimator) 조건에서도 학습 범위(≤3.2) 안이면 순위가 그대로다** — s=1.5 98.1% >
  s=1.0 95.3% > 기준 92.4%, 범위 안 붕괴는 24회 중 1회. 다만 **외삽 구간(3.5~4.0)의 붕괴가
  정확히 두 배**가 된다(s=1.0 4/8→8/8, s=1.5 1/8→4/8). **명령을 3.2 로 캡하고 s=1.5 를 쓰는 것**이
  처방이다.
- **`command_uniform_mirror` 는 겨눈 축은 고쳤지만 더 나은 정책은 아니다.** 같은
  `vel_err_scale=1.0` 에서 학습측 비대칭이 0.630 → 0.065 로 떨어지고 배포 외삽 붕괴가
  8/8 → 1/8 이 된다 — 진단한 기전이 맞았다는 직접 증거다. 그러나 추종(범위 안 93.0%)과 정지
  출발(배포 start 2.5% · duty 0.01)이 따라오지 않아 s=1.5 를 대체하지 못한다.
- ★ **영상은 측정이 아니다.** 카메라를 켜고 렌더하면 같은 플래그인데도 붕괴율이 25% → 80% 로
  뛴다(§6). 판정 수치는 전부 헤드리스 램프 값이다.

## 1. 이 문서가 보완하는 것

같은 저장소의 다른 세션이 GT 조건으로 3 arm × 8회 램프를 이미 냈다
(`../arch_scaling_study/figures/velscale_verdict_50k.png`, `metrics/velscale_ramp_50k.md`).
그 그림은 onset / 달성률 / 붕괴 세 면을 덮는다. **중복 실행하지 않았고**, 그 디렉토리에 쓰지도
않았다. 여기서는 빠진 축만 채운다.

| 빠져 있던 것 | 여기서 채운 것 |
|---|---|
| 학습 지표 ↔ 실측 자세의 연결 | `Mean symmetry loss` 궤적과 램프 실측 쏠림을 한 그림에 |
| 배포 조건 | `--use_estimator` 로 3 arm × 4회 재측정 |
| 영상 | 기존 램프는 `--no_video` 라 mp4 가 없었다 |

## 2. 측정 조건

기존 GT 램프의 npz 메타데이터를 그대로 맞췄다. 프로토콜이 다르면 같은 표에 넣을 수 없다.

| 항목 | 값 |
|---|---|
| 체크포인트 | `model_49999.pt` (3 arm 모두 매칭) |
| 명령 프로파일 | 0 → 4.0 → 0 사다리꼴, 0.5 m/s 단위, hold 3.0 s / ramp 2.0 s |
| 정책 주기 | dt 0.02 s (50 Hz) |
| heading | `--heading_hold` (kp 3.0) |
| DR / push | 둘 다 ON |
| 리셋 | `--force_stand` → `reset_strategy=random_stand` |
| 데이터셋 | `--run_params` 로 학습 cfg 복원 (`new_smr_leg_pkl` = ds14) |
| `use_estimator` | GT 표 = False, 배포 표 = True |

세 arm 은 학습 시 `reset_strategy: random`, `cmd_deadzone: 0.0`, `torque_penalty_w: 0.0` 을
공유한다(하이드라 오버라이드 누락). 결손이 공유되므로 arm 간 비교는 유효하다.

## 3. GT 조건 판정 (n=8)

붕괴 롤아웃을 **포함**한 값이다. 배포 기대값에 해당한다.

| | steady (2.0~4.0) | start (cmd 0.5) | duty | skew | 변위 | 붕괴 |
|---|---|---|---|---|---|---|
| 기준 s=0.5 | 87.6% | 1.6% | 0.03 | 0.158 | 133.3 m | 0/8 |
| s=1.0 | 92.8% | 14.0% | 0.50 | 0.402 | 114.6 m | **4/8** |
| **s=1.5** | **96.6%** | **71.8%** | **0.99** | **0.123** | **151.4 m** | 1/8 |

- `steady` = cmd 2.0~4.0 상승 구간 달성률, `start` = cmd 0.5 상승 구간 달성률
- `duty` = cmd 0.5 hold 구간에서 `|jvel| RMS > 0.4` 인 스텝 비율. 0 이면 "느리게 걷기 실패"가
  아니라 **아예 걷지 않음**이다
- `skew` = 롤아웃별 `|FL+FR hip| + |HL+HR hip|` 을 먼저 절대값 취한 뒤 평균

★ **쏠림 정의 주의.** 위 `skew` 와 `figures/` 의 (b) 패널은 **롤아웃별 절대값을 먼저** 취한다.
다른 세션 표의 `쏠림` 열은 부호를 살려 롤아웃을 먼저 평균하므로, 반대 방향으로 쏠린 롤아웃이
서로 상쇄된다. **같은 run 을 다르게 요약한 것이라 두 값은 일치하지 않으며, 이쪽이 항상 크거나
같다.** 두 문서가 충돌하는 게 아니다.

## 4. 그림

![symmetry and deploy](figures/symmetry_and_deploy.png)

- **(a) 학습측 비대칭** — s=1.0 이 ~32k 에서 기준을 추월한다. 24k 이전에 보면 정반대로 읽힌다.
- **(b) 걷는 동안의 자세 쏠림** — `duty < 0.5` 인 (롤아웃, 명령) 칸은 뺐다. 서 있는 로봇도 hip 에
  정적 오프셋이 있어 쏠림처럼 보이는데 그건 보행 비대칭이 아니다. 저속대(음영)는 서기→보행 전이
  구간이라 해석에 주의가 필요하다. s=1.0 의 cmd 4.0 점은 **넘어지지 않은 4개만의 평균**이라
  생존 편향이다.
- **(c) 배포 조건** — 실선 GT, 점선 estimator.

## 5. 배포(estimator) 조건

기존 램프 3종은 전부 `use_estimator=False` — env 의 ground-truth base 속도를 actor 에 그대로
넣은 조건이다. 실기는 그 값을 못 재고, 학습 롤아웃도 estimator 출력을 쓴다
(`ppo_parkour.py:185`). 그래서 `--use_estimator` 로 3 arm × 8회를 다시 쟀다 (GT 와 같은 표본).

전체 표는 `metrics/velscale_50k_gt_vs_estimator.md`.

| 조건 | arm | 붕괴 ≤3.2 | 붕괴 >3.2 | 달성률 2.0~3.2 | 달성률 2.0~4.0 | start | duty | skew | 변위 |
|---|---|---|---|---|---|---|---|---|---|
| GT | 기준 0.5 | 0/8 | 0/8 | 91.4% | 87.6% | 1.6% | 0.03 | 0.150 | 133.5 m |
| GT | 1.0 | 0/8 | **4/8** | 96.2% | 92.8% | 14.0% | 0.50 | 0.430 | 114.7 m |
| GT | **1.5** | 0/8 | 1/8 | **98.9%** | **96.6%** | **71.8%** | **0.99** | **0.123** | **151.4 m** |
| GT | 1.0 + mirror | 0/8 | 3/8 | 93.0% | 89.5% | 15.3% | 0.35 | 0.188 | 139.8 m |
| EST | 기준 0.5 | 0/8 | 0/8 | 92.4% | 88.4% | 10.0% | 0.21 | 0.222 | 135.6 m |
| EST | 1.0 | 0/8 | **8/8** | 95.3% | 82.2% | 49.5% | 0.67 | 0.381 | 69.6 m |
| EST | **1.5** | 1/8 | 4/8 | **98.1%** | **95.1%** | **70.8%** | **1.00** | 0.166 | 79.4 m |
| EST | 1.0 + mirror | **2/8** | 1/8 | 94.4% | 89.0% | **2.5%** | **0.01** | 0.210 | 143.3 m |

★ **붕괴 판정은 변위 기준(< 110 m)이다.** 처음에는 종료 시 접힘 비율(thigh/calf < -0.6 rad)로
쟀는데, mirror arm 은 **덜 접힌 채로 주저앉아** folded 0.12 인데 변위가 71 m 인 회차가 나온다.
변위는 관측이 완벽히 이봉성(완주 131~154 m vs 붕괴 63~86 m)이고 4 arm 전부에서 일관되며,
다른 세션 표의 base 0/8 · s=1.0 4/8 · s=1.5 1/8 도 그대로 재현한다. 접힘 기준으로는 mirror 가
2/8 로 과소 계수됐다.

**★ 붕괴는 전부 외삽 구간에서 시작한다.** 붕괴 시작 명령을 재 보면 GT·EST 통틀어
cmd 3.5~4.0, t=41~48 s 다. 학습 상한이 `lin_vel_x_max=3.2` 이므로 램프의 3.5 / 4.0 구간은
세 arm 모두 배운 적 없는 영역이다. 예외는 EST s=1.5 의 한 회차로, 하강 구간 cmd 0.4 @ t=80 s
에서 정지하다 넘어졌다 — 유일한 "범위 안" 붕괴다.

**학습 범위(≤3.2) 안에서는 estimator 를 써도 순위가 그대로다.** 달성률 s=1.5 98.1% >
s=1.0 95.3% > 기준 92.4% 이고, 범위 안 붕괴는 24회 중 1회뿐이다.

**estimator 가 바꾸는 것은 외삽 구간의 여유다.** 붕괴가 s=1.0 은 4/8 → **8/8**, s=1.5 는
1/8 → 4/8 로 정확히 두 배가 된다. 기준(0.5)만 두 조건 모두 0/8 인데, 그 대신 정지 출발을
못 하고(start 1.6~10.0%, duty 0.03~0.21) 가장 느리다.

→ **실용 처방: 명령을 3.2 로 캡하고 s=1.5 를 쓴다.** 캡은 이미 `vmax32` 로 쓰던 설정이다.
캡 없이 4.0 을 명령하면 배포 조건에서 s=1.0 은 전멸, s=1.5 도 절반이 넘어진다.

### 5-1. `command_uniform_mirror` arm

`vel_err_scale=1.0` 을 그대로 두고 **expert 가중치 방식만** `command_uniform_mirror` 로 바꾼
arm(`velscale10_ds14_cumirror_vmax32`, 50k 완주). 학습측 대칭 지표에서는 극적이다:

| iter 45k | 기준 0.5 | 1.0 | 1.5 | 1.0 + mirror |
|---|---|---|---|---|
| `Mean symmetry loss` | 0.325 | **0.630** | 0.067 | **0.065** |

**s=1.0 의 발산이 사라진다 (0.630 → 0.065, 9.7배).** 25k 이후 0.058~0.066 에서 멈춰 s=1.5 와
동률이다. `command_uniform` 의 미러 맹점(짝 없는 0.6 s 클립이 expert 질량의 20.2% 를 차지)이
정책 비대칭의 실제 원인이었다는 직접 증거다 — 보상 함수는 건드리지 않았다.

**램프 실측도 그 방향으로는 확인된다.** s=1.0 대비 붕괴가 GT 4/8 → 3/8, EST **8/8 → 1/8**(외삽
구간) 로 줄고, skew 가 0.430 → 0.188 (GT) · 0.381 → 0.210 (EST) 로 낮아진다.

**그러나 s=1.5 를 대체하지는 못한다.** 두 가지가 따라오지 않는다.

- **추종**: 범위 안 달성률 93.0%(GT) / 94.4%(EST) 로 s=1.0(96.2 / 95.3) 보다도 **낮고**
  s=1.5(98.9 / 98.1) 에 크게 못 미친다.
- **정지 출발**: GT start 15.3% / duty 0.35 로 s=1.0 수준이고, **배포 조건에서 2.5% / duty 0.01
  로 무너진다** — 전 arm 중 GT→EST 낙폭이 가장 크다. 범위 안 붕괴도 EST 2/8 로 가장 많다.

★ **학습측 `Mean symmetry loss` 는 대칭·붕괴 축만 예측하고 보행 개시·추종은 예측하지 못한다.**
mirror 와 s=1.5 는 이 지표에서 0.065 vs 0.067 로 사실상 같은데, 램프에서는 start 15.3% vs
71.8% 로 갈린다. 학습 지표 하나로 능력을 판정하면 안 된다는 사례가 하나 더 늘었다.

★ mirror arm 의 `Mean reward`(411.5) 와 `amp_reward`(36.9) 가 전 arm 중 가장 높지만
**비교 불가**다 — expert 클립이 14 → 18 개로 달라 discriminator 가 푸는 문제 자체가 다르다.
같은 보상 함수인 `lin_vel_reward` 는 46.09 vs s=1.0 의 45.87 로 사실상 동률이고, 실제 능력은
램프가 보여주듯 더 낮다.

★ 붕괴 시작 시점은 **끝까지 이어지는 접힘 구간의 시작**으로 잡았다. 정상 보행 중에도 calf 가
일시적으로 -0.6 rad 를 넘으므로 첫 교차로 재면 t=14~18 s / cmd 1.0~1.5 라는 틀린 값이 나온다.

### ★★ 영상은 측정이 아니다 — 카메라를 켜면 붕괴율이 3배가 된다

영상용 렌더는 `--no_video` 를 빼서 `enable_cameras=True` 로 돈다. 플래그는 그 외 전부 동일한데
(npz 메타데이터로 확인: `heading_hold` / `no_dr` / `no_push` / `reset_strategy` / `hold_s` /
`ramp_s` 일치) 결과 분포가 다르다.

| arm | 영상 (카메라 ON) | 헤드리스 램프 |
|---|---|---|
| baseline 0.5 | 0/1 | 0/8 |
| scale 1.0 | 2/2 | 4/8 |
| scale 1.5 | 1/2 | 1/8 |
| 1.0 + mirror | **5/5** | 3/8 |
| **합계** | **8/10 = 80%** | **8/32 = 25%** |

mirror arm 은 완주 회차를 얻으려고 5회를 렌더했는데 전부 넘어졌다 — 램프 붕괴율 3/8 이면
확률 0.7% 다. **판정 수치는 전부 헤드리스 램프에서 나온 값이고, 영상은 거동을 눈으로 보기 위한
것일 뿐이다.** 기전은 규명하지 않았다(렌더 케이던스가 DR·push 의 난수 소비나 스텝 타이밍에
영향을 주는 것으로 추정되나 미검증).

★ 그래서 **mirror arm 비교 영상은 싣지 않았다.** 완주 회차가 나올 때까지 계속 돌려서 고르는 것은
다른 조건에서 결과를 선택하는 것이라 판정을 왜곡한다. mirror 의 실제 붕괴율은 표의 3/8 이다.

★ s=1.5 의 첫 렌더(`vsvid_vs15_1`)도 붕괴 회차였고 두 번째(`vsvid_vs15_2`, 변위 152.5 m)를 썼다.
위 카메라 효과를 알기 전의 선택이라, 이 영상 역시 대표성보다 **예시**로 봐야 한다.

★ 영상 후반 배경이 흰 것은 로봇이 130 m 넘게 달려 바닥 텍스처 영역을 벗어난 렌더 아티팩트다.
물리와 무관하다.

원본 단일 영상은 `_workspace/leg/vsvid_*/speed_ramp-step-0.mp4` 에 있다.

## 7. 다음 액션

정하지 않고 남겨 둔 것들이다.

1. **`command_uniform_mirror` 를 어떻게 할지.** 두 갈래가 있고 어느 쪽인지는 판단이 필요하다.
   - **폐기** — 배포 조건 범위 안 붕괴가 2/8 로 전 arm 중 가장 많고 정지 출발이 무너진다.
   - **`1.5 + mirror` arm** — 두 처방이 서로 다른 축을 고치므로(s=1.5 = 추종·개시,
     mirror = 대칭·붕괴) 겹칠 여지가 있다. 다만 s=1.5 는 이미 대칭이 좋아(0.067) mirror 가
     더할 여지가 작을 수 있다.
2. **카메라 ON 붕괴율 상승의 기전** (§6). 8/10 vs 8/32 는 우연으로 보기 어렵다. 렌더 케이던스가
   DR·push 난수 소비를 바꾸는지 확인이 필요하다. 확인 전까지 **영상으로 능력을 판정하면 안 된다.**
3. **`reset_strategy=random_stand` 재학습.** 네 arm 모두 학습 시 `random` 이라(하이드라 오버라이드
   누락) `rel_stand_envs: 0.1` 이 무시됐다. 결손이 공유돼 arm 간 비교는 유효하지만, 정지 출발
   절대값은 여전히 낮은 쪽에 갇혀 있다.
4. **17-DOF `export_deployable`** 이 아직 없다. 실기 배포 경로가 비어 있다.
