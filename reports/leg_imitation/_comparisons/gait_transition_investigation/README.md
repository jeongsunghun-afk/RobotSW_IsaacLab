세 갈래로 나뉜 문서를 한 줄기로 묶는다. 개별 근거·원자료는 각 문서에 있다.

- [`cmdchg_in_episode_command`](../cmdchg_in_episode_command/README.md) — 처방 ③

## 출발한 질문

> 학습 중간 영상에는 gallop 하는 개체가 분명히 보이는데, 판정에 쓴 램프 영상에는 하나도 없다.

## 한 문장 결론

**걸음을 고르는 것은 명령이 아니라 에피소드의 초기 자세다.** 이 결합은 초기화를 조건화해도
(처방 ②), 에피소드 도중 명령을 바꿔도(처방 ③) 끊어지지 않았다.

## 확정된 사실 5가지

### 1. 걸음은 초기 자세가 잠근다 — 명령이 아니라

같은 정책 · 같은 명령 분포 · 4096 env, **초기 자세만** 바꾼 대조:

| model_30000, cmd 2.5\~3.5 | 참조 프레임(RSI) 출발 | 정지 출발 |
|---|---|---|
| baseline | 24.8% | **0.0%** |
| rsimatch | **68.2%** | **0.0%** |

한 번 정해진 걸음은 에피소드 내내 유지된다(1\~3 s 창의 걸음이 6\~8 s 창에도 587/589, 1798/1806).

### 2. 참조 데이터에는 속도-보행 사다리가 **있다**

| 클립 평균속도 | 클립 | 보행 |
|---|---|---|
| 0.11\~0.94 m/s | `leg_walk*` | walk / trot |
| **1.97 m/s** | `leg_trot0`(+mirror) | **pace** ← 이름과 달리 pace |
| **2.69\~3.03 m/s** | `leg_run0`, `leg_run1`(+mirror) | **gallop** |

정책은 둘 다 배웠지만 **사다리는 재현하지 않는다** — 정지에서 출발하면 4.0 까지 pace 로 가고
바뀌는 것은 주파수뿐(2.05 → 2.57 Hz).

### 3. 판별자는 이미 옳은 신호를 준다 — 문제는 보상 설계가 아니다

학습된 판별자로 style 보상을 직접 측정:

| 속도 구간 | gallop style | pace style | 차이 |
|---|---|---|---|
| 2.5\~3.0 | 0.879 ±0.06 | 0.540 ±0.07 | +0.339 |
| **3.0\~3.3** | 0.840 ±0.05 | **0.411 ±0.04** | **+0.429** |

표준편차 0.04\~0.07 이니 여러 시그마다. **정책은 style 보상 0.43 을 버리면서 pace 를 고수한다.**

### 4. ★ 명령이 에피소드 내내 바뀌지 않았다 (`_post_physics_step` 미호출)

타이머를 감소시키는 메서드를 `DirectRLEnv.step()` 이 부르지 않는다. 실측으로 먼저 확인했다 —
**4096 env · 8 s 에서 명령이 바뀐 env 0/4091**. `tar_change_time`(4\~7 s)은 죽은 설정이었고,
정책은 "달리는 중 명령 변화"를 한 번도 겪은 적이 없다.

→ 고쳐서 되살렸다(`resample_command_in_episode`, 기본 False). 같은 죽은 훅이
`go2_imitation_tracking_env.py` 에도 **남아 있다**(미수정).

### 5. 이전 판정들의 유효 범위

`vel_err_scale=1.5` 판정을 포함해 이 프로젝트의 램프 기반 결론은 전부
**"명령 고정 + 정지 출발"** 조건에서 잰 것이다. 틀린 게 아니라 **적용 범위가 좁다**.

## 처방 두 건 — 둘 다 기각

### ② `rsi_match_command` — RSI 클립을 명령 속도에 맞춰 뽑기

RSI 격자만 보면 성공처럼 보인다: cmd 2.5\~3.5 의 gallop 이 24.8% → **68.2%**(30k) → 72.7%(40k),
중속은 6.4% 로 **10.7 배 단조**. 그러나 **정지 출발 대조가 0.0%** 라 그 상관은 전환 능력이 아니라
**초기화 artifact** 다 — 매칭은 "gallop 자세 출발 → 항상 고속 명령"을 만들 뿐이다.

명령 분포 왜곡은 없었다(20만 표본: 명령 mean/std 불변, 클립 주변분포 ±1%p, mirror 편차 0.06%p).
**설계가 아니라 겨냥한 변수가 틀렸다.**

### ③ `resample_command_in_episode` — 에피소드당 1.2회 명령 변경

| 지표 | @20k | @30k | @40k | @42.4k(마감) | baseline |
|---|---|---|---|---|---|
| **저속→고속** (pace→gallop) | **0/193** | **1/188** | **0/204** | **0/86** | 표본 없음 |
| 고속→저속 (gallop→pace) | 23/64 (36%) | 23/91 (25%) | 16/84 (19%) | 6/38 (16%) | 표본 없음 |
| 속도 선택성 (1.5\~2.5 → 2.5\~3.5) | 17.9 → 14.4 | 14.3 → 13.5 | 15.9 → 19.6 | 19.8 → 15.4 | 24.1 → 21.8 |
| 초기자세 대조 (RSI vs 정지) | 14.4 vs 0.3 | 13.5 vs 0.2 | 19.6 vs **0.0** | 15.4 vs **0.0** | 22.2 vs **0.0** |

**원하는 전환은 네 지점 합쳐 1/671 (0.15%).** 아래쪽 방향은 15\~36% 로 계속 살아 있어
**프로브가 못 잡는 게 아니다.** gallop 최고점은 참조 gallop 속도(2.69 m/s)보다 아래에 머물고
(40k 에서 cmd 1.0, 42.4k 에서 cmd 2.0), 고속 칸에서 오히려 내려간다.

이 팔은 42.4k 에서 중단했다 — 추세가 역방향이라는 판단이었고, 마감 판정이 그것을 바꾸지 않았다.
**처방 ③ 기각.** 훅 수정 자체는 버그 픽스이므로 유지하되 `resample_command_in_episode` 기본값은
False 로 남긴다.

## 남은 갈래

에피소드당 명령 변경이 **1.20 회**(실측: 1회 79.6% · 2회 20.2%)에 그쳤다는 점에서 두 해석이
남아 있었다:

- **(가) 신호는 충분한데 못 배운다** — 최적화 우물 문제
- **(나) 신호가 얇았다** — 노출량 부족

→ 후속 팔 `cmdchg4s_ep20`(에피소드 20 s · 4 s 고정 주기 = **4회/에피소드**, 3.3 배)이 이를 가른다.
그 위에 사용자가 **속도 조건부 discriminator** 팔 두 개(`condspeed_*`)를 얹어 진행 중이다.

## 측정 함정 — 전부 실제로 값을 바꿨다

이 조사에서 **도구 결함이 결론을 뒤집을 뻔한 경우가 6 건**이다. 같은 실수를 반복하지 않도록 남긴다.

| 함정 | 증상 | 결과 |
|---|---|---|
| 램프의 `_RESTORE_KEYS` 에 `motion_weight_mode` 누락 | 소스 기본 `length` 로 평가 → 학습(`command_uniform`)과 다른 클립 분포 | 고정 3.0 RSI 출발 gallop **0/6 → 4/6** |
| 램프에 `rsi_match_command` 누락 | 매칭이 **꺼진** env 를 재고 있었다 | 처방 ② 를 "효과 없음"으로 오판할 뻔 |
| 전환 프로브가 "변경 정확히 1회" 인 env 만 사용 | 4 s 주기에서 표본 전멸 → "전환 0" 과 화면상 동일 | 변경마다 표본화로 수정(기존 팔 수치 불변, 표본 288→523) |
| 조사 `--dur_s 10` 이 10 s 에피소드 경계와 겹침 | 마지막 창이 리셋을 걸쳐 4096 → **1** 표본 | 격자는 `--dur_s 8` 로 분리 |
| 실제 속도를 롤아웃 전체로 평균 | 명령이 바뀌는 run 에서 cmd 0\~0.5 칸에 **1.06 m/s** | 분류 창에서만 평균내도록 수정 |
| FFT 한 빈의 위상으로 보행 판정 | hold 1.8 s → 빈 0.56 Hz 라 세 팔·세 명령이 모두 "2.20 Hz" | Hilbert 순시 위상으로 교체 |

추가로: **참조 pkl 의 `frames` 는 관절 앞에 root 6 열이 붙어 있다**(`frames.shape[1] - len(dof_names)`
로 오프셋을 구할 것). 넘어진 롤아웃·리셋 걸친 창은 반드시 제외할 것 — 누워 버둥거려도 순시
위상은 나오므로 무엇으로든 분류된다.

## 방법론 교훈 하나

**격자(population) 상관만으로 판정하면 안 된다.** 처방 ② 는 격자에서 10.7 배 단조 증가라는
교과서적 성공 신호를 냈지만, 초기 자세를 고정한 대조 한 칸(정지 출발 0.0%)이 그것을 뒤집었다.
연관을 만든 것과 능력을 만든 것은 다르고, **둘을 가르는 것은 언제나 통제 조건**이다.
