# hip 이 soft limit 에 붙는 이유 — 정책 출력이 **포화 상수**였다 (2026-09-02)

09-02 A/B 에서 hip 한계 밀착이 초기 자세와 무관함이 드러났다(처짐 없이 출발해도 2 초면 같은 자리).
남는 후보는 정책 자신이었고, 클램프 **이전** 출력을 보니 답이 바로 나왔다.

측정: `_workspace/hindleg_hip_action_probe.py` (512 env · 500 스텝 · 기립 스텝만 · 표본 25.6 만).
`hindleg_gait_probe`·`trip_probe` 와 달리 **클램프 전 목표**를 env 와 같은 식으로 재구성한다:

```
target_preclamp = action_scale * action + default_joint_pos     (action_scale 0.25, default 전부 0)
target          = clamp(target_preclamp, soft_lo, soft_hi)
```

## 1. ★HR_hip 은 제어축이 아니다 — 상수 −13 을 내고 100 % 잘린다

baseline `model_39799`, cmd 0.3 (다른 명령도 같은 그림):

| 관절 | 가동폭 | action mean | std | \|mean\|/std | 상단 클램프 | 하단 클램프 | 초과량 p99 | 위상상관 |
|---|---|---|---|---|---|---|---|---|
| **HL_hip** | 0.468 | +0.779 | 1.943 | **0.40** | 33.9 % | 0.8 % | 0.275 | +0.05 |
| **HR_hip** | 0.468 | **−12.605** | 1.282 | **9.83** | 0.0 % | **99.9 %** | **3.727** | +0.22 |
| HL_thigh | 3.141 | −0.292 | 1.159 | 0.25 | 0.0 % | 0.0 % | 0.000 | −0.77 |
| HR_thigh | 3.141 | +0.112 | 1.292 | 0.09 | 0.0 % | 0.0 % | 0.000 | −0.79 |
| HL_calf | 1.719 | −0.285 | 1.736 | 0.16 | 0.1 % | 7.3 % | 0.205 | −0.62 |
| HR_calf | 1.719 | +0.466 | 1.934 | 0.24 | 15.9 % | 0.1 % | 0.321 | −0.62 |

| HR_foot | 1.728 | +6.426 | 6.185 | 1.04 | **70.7 %** | 0.3 % | 3.479 | +0.93 |

읽는 법 셋:

1. **`|mean|/std` = 9.83.** HR_hip 은 진동이 아니라 **상수 오프셋**이다. 다른 축은 전부 0.09~1.04 —
   평균이 표준편차 안에 있다(= 위상에 실린 진동). hip 만 자릿수가 다르다.
2. **초과량 p99 = 3.727 rad.** hip 가동폭이 0.468 rad 이므로 정책은 **가동범위의 8 배**를 넘겨
   요구하고 있다. 클램프가 없으면 목표각이 −3.4 rad 다.
3. **위상상관 +0.22.** thigh/calf/foot 은 |r| 0.62~0.93 으로 gait clock 에 실려 있는데 hip 은 0 에
   가깝다 ⇒ 보행 동작이 아니라 **자세 편향**이다.

⇒ **HR_hip 에서 클램프가 컨트롤러다.** 정책 출력은 99.9 % 시간 동안 아무 정보를 싣지 않고,
관절은 soft limit 에 눌려 있다. 08-28 실기 캡처에서 HR_hip 목표가 **100 % 하한 클램프**였던 것과
같은 현상이며, 실기 고유 문제가 아님이 이것으로 확정된다.

HL_hip 은 다르다 — mean +0.78 · std 1.9 로 정상 축에 가깝지만 클램프율이 34 % 다.
**foot 두 축(67~71 %)도 같은 병**이고 hip 보다 덜할 뿐이다.

## 2. 학습 로그에 클램프 발동률을 남긴다

이 사실이 6 일 넘게 안 보인 이유는 **학습 로그에 클램프가 없었기 때문**이다. `_pre_physics_step`
이 조용히 자르고 아무 데도 신고하지 않았다. `Episode_Clamp/<joint>` 추가 —
`hind_leg_env.py` 가 관절별로 "목표가 잘린 스텝의 비율"을 에피소드 평균으로 로깅한다.

⚠ 이 값이 다음 학습에서 hip 99 % 로 찍히면, 그 run 은 **hip 제어 권한 없이** 학습된 것이다.

## 3. 좌우 4.17 배 부하 차 — sim 은 대칭이다

`_workspace/hindleg_hip_gravity_probe.py`: sysid env(`fix_base=True`, 실기 공중 고정과 같은 전제)
에서 hip 을 각도별로 홀드하고 정착 후 `applied_torque` 를 읽는다. HL/HR 을 거울 자세로 잡는다.

| | 값 |
|---|---|
| 좌우 대칭비 HL/HR (13 각도) | **중앙 0.982** (범위 0.132~3.056) |
| 한계 근방(\|q\|>0.15) sim 유지토크 | HL **11.36** · HR **12.38** N·m |

**sim 은 대칭이다.** 그러므로 실기의 4.17 배 차는 기구 형상에서 나올 수 없다.

실기 대조:

| 동작점 | sim | 실기 | 실기/sim |
|---|---|---|---|
| HL_hip q +0.164 | 11.4 급 | 6.245 N·m | **0.53배** |
| HR_hip q −0.234 | 12.4 급 | 1.497 N·m | **0.12배** |

★**HR 이 이상치다.** 두 값 다 sim 보다 낮은데(공중 매단 리그가 하중을 일부 받쳤을 가능성),
HR 은 자릿수가 다르다 — sim 이 12 N·m 를 요구하는 자세에서 실기는 1.5 N·m 로 버틴다.

남는 후보 둘:

- **영점 오차** — HR_hip 의 실제 물리 자세가 중력 중립점 근처인데 엔코더가 −0.234 라고 보고한다.
  `zero_deg` 가 8 축 전부 0(미캘리브레이션)이라는 사실과 곧바로 이어진다.
- **리그 지지** — 매단 구조가 한쪽을 더 받쳤다.

⚠ 이 프로브는 **중력+게인이 요구하는 토크**만 잰다(실기 마찰 없음). 그리고 n=1 env 단발이라
개별 각도의 대칭비는 0.13~3.06 으로 흔들린다 — **중앙값과 한계 근방 평균만** 신뢰할 것.

## 4. 다음

1. **hip 을 왜 그쪽으로 미는가** — 보상항 중 hip 을 한 방향으로 미는 것을 찾는다.
   `similar_to_default`(−0.01/−0.1)는 반대로 0 으로 당기는데도 −13 이 나온다.
   후보: `flat_orientation_l2`·`ang_vel_xy_l2` 가 몸통 자세를 잡으려고 hip 을 쓰는 경로.
2. **포화 액션이 obs 로 되먹임된다** — `prev_action` 이 관측에 들어가므로 −13 이라는 값이
   매 스텝 네트워크 입력으로 돌아온다. 다른 축이 ±2 인데 한 축만 −13 이면 입력 스케일이 왜곡된다.
   행동 클리핑(`clip_actions`)이 실제로 걸리는지부터 확인할 것.
3. **`zero_deg` 실측** — §3 의 두 후보를 가르는 가장 싼 수단이다. probe 모드 채널각 출력을
   `calib_bipedleg.hpp` 에 옮기면 된다(순서: 로봇을 sim 중립자세에 정렬 → probe → 복사 → 재빌드).
