# 토크 페널티 2배 fine-tune — 토크 15.7 % 감소, 실제 속도는 무손실

> 작성 일시: 2026-09-07 10:50 (§9·§10 추가 2026-09-07 13:10)
> 비교 대상: `2026-09-07_09-18-24_torque2x_ft` (`joint_torque_reward_scale = -0.0004`) vs `2026-09-02_09-07-14_resetnoise_ft` (`-0.0002`) — 다른 점: 이 스케일 **하나**. 전자가 후자의 `model_44798.pt` 에서 이어받았다

## BLUF

`joint_torque_reward_scale` 을 −0.0002 → −0.0004 로 올리고 5000 iter(44,798 → 49,797) fine-tune 했다.

**`sum(τ²)` 이 15.7 % 줄었다.** 정책이 안 바뀌었다면 스텝당 항 값이 정확히 2배가 돼야 하는데 1.687 배에 안착했다. 학습 지표상 대가는 속도 추종 **−1.3 %**(0.5841 → 0.5768) 하나뿐이고, 그마저 아직 회복 추세다.

고정 명령 0.0 / 0.5 / 1.0 m/s 에서 두 정책을 같은 env 로 재 보면(§9) **실제 전진속도는 손실이 없고**(차이 ±0.01 m/s 로 산포 안), 토크 감소는 속도가 붙을수록 커진다(−6.5 / −10.1 / **−12.1 %**). 학습 로그의 `track_lin_vel_xy_exp` −1.3 % 는 지수 매핑이 만든 확대다.

**단 이 15.7 % 는 sim 토크다.** 페널티를 올린 근거였던 "실기 thigh 가 채널 15 N·m 를 6.9 % 초과" 는 실기 캡처에서 온 값이고, 이번 학습은 그 수치를 직접 건드리지 않는다 — 확인하려면 새 실기 캡처가 필요하다.

## 3. 토크가 실제로 줄었는가 — 그렇다

`Episode_Reward/*` 는 **에피소드 합**이라 에피소드 길이에 비례한다(§3-a 로 확인). 두 run 의 `ep_len` 이 963.6 vs 968.3 으로 달라 스텝당으로 정규화한 뒤 각자의 스케일로 나눠야 같은 자가 된다:

```
baseline  -1.4349e-04 / 963.6 정규화 후 / 0.0002 / 0.02  ->  sum(τ²) = 35.9
torque2x  -2.4206e-04 / 968.3 정규화 후 / 0.0004 / 0.02  ->  sum(τ²) = 30.3
                                                             -----------
                                                                -15.7 %
```

RMS 로는 −8.2 % 다(제곱합이라).

baseline 의 35.9 는 09-04 캡처 보고서 §9-c 에서 로깅 규약을 **가정하고** 역산했던 값과 정확히 같다 — 그 가정(에피소드 합)이 이번에 확인됐다.

### 3-a. "정책 불변" 기준선을 switch 순간에서 읽을 수는 없다

이상적인 대조는 "스케일이 바뀐 직후, 아직 적응하지 않은 같은 정책" 이다. 그 값을 로그에서 직접 읽어 보면 쓸 수 없다:

| switch 이후 | `ep_len` | 스텝당 항 / (baseline 스텝당 × 2) |
|---|---|---|
| 1 iter | 18 | 2.44 |
| 5 iter | 107 | 1.71 |
| 20 iter | — | 1.23 |
| 50 iter | — | 1.08 |

resume 직후엔 전 env 가 리셋돼 에피소드가 18 스텝짜리이고(합이 작아지는 방향), 동시에 랜덤 리셋 자세에서 복구하느라 **스텝당 토크는 정상보다 크다**(비율이 2.44 로 시작). 두 오염이 반대 방향으로 겹쳐 어느 지점도 기준선이 못 된다.

그래서 기준은 **baseline 의 정상상태 × 2** 를 쓴다. 정책이 안 바뀌었다면 스텝당 항이 정확히 2.000 배여야 하고, 실측 안착값은 **1.687 배**다.

**적응이 빨랐다.** 첫 500 iter 평균이 이미 −0.2388 이고 남은 4500 iter 동안 −0.2325 까지 2.6 % 더 갔다. 곡선이 평평해졌으니 이 스케일에서 짜낼 수 있는 건 거의 다 나왔다.

## 4. 대가 — 학습 지표상 추종 1.3 %, 그리고 회복 중

> ⚠ 이 −1.3 % 는 **학습 지표**(`track_lin_vel_xy_exp`)다. 고정 명령에서 실제 속도로 다시 재면 손실이 아니다(§9) — `exp(−err²/0.1)` 매핑이 작은 오차 변화를 증폭한다.

`lin_vel` 이 0.5459 로 떨어졌다가 0.5765 까지 **단조 회복**했다. baseline 최종이 0.5814 이니 격차가 0.005 까지 좁혀졌고 아직 상승 중이다. 더 돌리면 더 좁혀질 여지가 있다.

첫 구간의 `ep_len` 921 은 resume 과도구간이다 — baseline 도 39,799 에서 927 로 시작해 500 iter 만에 967 로 올라갔다. 스케일 변경 탓이 아니다.

**§9-b 에서 예상한 "추종을 포기하는 쪽으로 배운다" 는 이 규모에서는 일어나지 않았다.** 처짐 지표(`base_height` −0.5 %)도 사실상 무변화다.

## 5. 낙상 감소는 **판정 불가**

`base_contact` 가 0.2333 → 0.1683 (−27.9 %) 로 보이지만 **주장하지 않는다.** 이번 run 은 스케일 변경과 **추가 5000 iter** 를 같이 받았고, 낙상 대조군이 없다.

baseline 자신의 5000 iter 를 대조로 쓰면:

| | 추세 (per 1k iter) | 구간 내 범위 |
|---|---|---|
| baseline `base_ct` | −0.0034 | 0.162 ~ 0.213 |
| torque2x `base_ct` | −0.0113 | 0.171 ~ 0.258 |

추세는 3.3 배 가파르지만, **torque2x 최종 0.1683 이 baseline 자체 진동 범위(0.162~0.213) 안에 들어간다.** 잡음과 분리되지 않는다.

같은 이유로 `track_ang_vel_z_exp` +4.8 % 도 스케일 효과로 볼 근거가 없다.

## 9. 고정 명령 A/B — 0.0 / 0.5 / 1.0 m/s

학습 로그는 명령이 섞인 평균이라 "어느 속도에서 무엇이 달라졌는지" 를 못 가른다. 두 체크포인트를
**같은 env 인스턴스**에 번갈아 올려 명령을 고정하고 다시 쟀다.

공정성 전제: 두 run 의 `params/env.yaml` 이 `device`·`log_dir`·`joint_torque_reward_scale` 셋만 빼고
**동일**하다(보상 스케일은 동역학에 영향 없음). 그래서 env 를 하나만 만들어도 cross-plant 가 아니다.
롤아웃마다 같은 시드로 리셋한다. ⚠ 시드를 맞춰도 정책 간 초기상태가 비트 단위로 같지는 않다 —
같은 분포에서 잰 짝지은 비교이지 "같은 외란" 이 아니다.

`512 env × 300 step`(warmup 100 제외), seed 0.

| 지표 | cmd 0.0 | cmd 0.5 | cmd 1.0 |
|---|---|---|---|
| 실제 `vx` [m/s] | 0.002 → 0.011 | 0.472 → 0.479 | 0.923 → 0.913 |
| `vx` 스텝간 산포 (std) | 0.101 → 0.108 | 0.116 → 0.120 | 0.179 → 0.188 |
| **`sum(τ²)`** [N²m²] | 411 → **385** (**−6.5 %**) | 594 → **534** (**−10.1 %**) | 794 → **697** (**−12.1 %**) |
| 몸통 기울기 [deg] | 12.76 → **11.85** (−7.1 %) | 8.79 → **7.90** (−10.2 %) | 5.86 → **5.16** (−11.9 %) |
| base z [m] | 0.582 → 0.584 | 0.565 → 0.562 | 0.539 → 0.535 |
| `abs(qd)` p99 [rad/s] | 5.74 → 5.57 | 7.12 → 7.04 | 7.49 → 7.22 |

**속도 추종은 손실이 없다.** 다만 **이득이 있다고도 읽으면 안 된다** — 두 정책의 차이가 +0.008 /
−0.010 m/s 인데 스텝간 산포가 0.12~0.19 m/s 다. env 는 독립 표본이 아니고 스텝은 자기상관이 있어
유효 표본수가 `512 × 300` 보다 훨씬 작다. 부호를 읽을 만한 격차가 아니다.

말할 수 있는 것은 **학습 로그의 −1.3 % 가 실제 속도에서는 나타나지 않는다**는 것이다.
`track_lin_vel_xy_exp` 는 `exp(−err²/0.1)` 이라 작은 오차 변화를 크게 증폭하므로, 그 항으로 판정하면
대가를 과대평가하게 된다.

**토크 감소가 속도에 비례한다** (6.5 → 10.1 → 12.1 %). 정지에서는 덜 줄고 빨리 걸을수록 많이 준다.

**몸통 기울기가 전 명령에서 7~12 % 개선됐다.** 노린 것이 아닌 부수효과다.

### 9-a. 줄어든 것은 thigh 가 아니라 calf 였다

`cmd 1.0` 관절별 (`abs(τ)` 평균 / p95 / 채널 15 N·m 초과율):

평균보다 이쪽이 맞는 방향이다. **8축 전부 초과율이 내려갔다.**

| HL/HR_foot | 0.753/0.731 → 0.765/0.739 | 0.700/0.765 → 0.707/0.775 | 0.774/0.844 → 0.789/0.872 |
| HL/HR_calf | 0.008/0.013 → 0.007/0.010 | 0.123/0.194 → 0.147/0.149 | 0.161/0.221 → 0.171/0.190 |

**HR_hip 은 꿈쩍도 안 한다** — 예측 그대로다. 실기 채널 `abs(τ)` p95 가 0.67 N·m 로 8축 최저라
토크 항이 붙을 데가 없다. **HL_hip 은 최대 11 포인트 내려갔다** — 노린 것이 아니고 기전도 미규명이다.

### 9-c. 실기와 맞춰 볼 수 있는 한 지점

sim `cmd 0.0`(제자리, baseline `model_44798`)의 thigh 초과율이 **HL 3.74 % / HR 4.77 %** 이고,
09-04 실기 캡처(제자리 명령)가 **HL 6.86 % / HR 5.66 %** 다. 같은 자릿수다.

⚠ **단 정책도 다르다.** 실기 캡처가 돌린 것은 배포본 `model_39799`(`gainclamp_ft`)로, sim 쪽보다
**5,000 iter 이전** 체크포인트다. 그러니 이 일치를 "조건을 맞추면 sim 이 실기를 재현한다" 로만
읽을 수 없다 — 조건 효과와 체크포인트 차이가 섞여 있다. 같은 체크포인트로 실기를 다시 뜨면
갈린다(§8-1).

걷는 명령에서는 sim 이 13~16 % 로 크게 오르는데, 실기는 걷는 캡처가 없어 비교 대상이 없다.

## 10. 영상 — 추적 카메라

로봇 한 대(env 0)를 뒤·측면에서 따라가는 카메라(`viewer.origin_type=asset_root`)로 찍었다.
명령은 hydra 로 `command_cfg.lin_vel_x_range=[c,c]` · `rel_standing_envs=0` 로 고정했다. 각 8 초(400 step).

⚠ **영상은 예시이지 측정이 아니다.** 카메라를 켜면 붕괴율이 달라지는 것이 이 저장소에서 이미 확인됐다
(`project_leg_camera_on_changes_fall_rate`). 판정 수치는 §9 의 헤드리스 프로브가 담당한다.
**좋은 회차가 나올 때까지 재렌더하지 않았다** — 카메라 프레이밍만 두 번 고쳤고(너무 멀었다가 아래로
잘렸다) 정책 거동은 첫 회차를 그대로 쓴다.
