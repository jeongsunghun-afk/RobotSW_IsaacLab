**TXT → PKL 변환 경로** (`convert_smr_to_pkl.py` 실측, 코드 read 완료):

```
TXT 프레임(61열): [0:3]=root_pos  [3:7]=root_quat(xyzw)  [7:19]=joint_dof(12)  [19:]=버림(속도·접촉 등, motion_lib가 재계산)
PKL 프레임(18열): [0:3]=root_pos  [3:6]=root_rot(exp map, quat_to_exp_map)      [6:18]=joint_dof(12)
```

변환 비용은 파일당 O(N) numpy 연산(쿼터니언→exponential map)뿐이라 사실상 무료. 3,524개
전체를 일괄 변환해도 수 초 내 완료된다(`--src_dir`/`--dst_dir` 배치 모드 지원).

**관절 순서 대조 (최우선 확인 사항).** `smr_go2/new_dataset/walk.txt`를
`convert_smr_to_pkl.py`로 직접 변환해 `smr_go2_pkl/walk.pkl`과 바이트 단위 비교:

```
max|diff| = 0.0   (완전 일치)
```

그리고 저장소 현행 `smr_mirror_pkl/go2_walk.pkl`과도 비교:

```
max|diff| = 0.047   (거의 일치 — 후처리 버전 차이로 추정, 관절 순서/축 정의는 동일)
```

**결론: 관절 순서는 `smr_txt_retarget_dataset_go2_v0` → `smr_go2_pkl` → 저장소
`smr_mirror_pkl` 전 구간에서 동일한 컨벤션을 쓴다.** 별도 관절 리매핑 불필요.

## 2. 현행 8클립과의 계보 (md5 + 프레임 수 대조)

저장소 `source/.../go2_imitation/imitation/smr_mirror_pkl/go2_{name}.pkl` 9개(→ 고유 8개, `trot1`=`trot0` 중복)는
**이름이 정확히 `smr_go2_pkl/{name}.pkl`(jump류 제외 9개)과 일치**하고, 프레임 수도 동일(198 등).
md5는 다르지만(`smr_go2_pkl/walk.pkl`과 저장소 `go2_walk.pkl` 사이 값 최대 오차 0.047) 이는 바이트
재현이 아니라 **동일 소스의 소폭 후처리 버전 차이**로 보인다.

계보 확정:

```
smr_txt_retarget_dataset_go2_v0/{cat}/*.txt (수천 개 raw 리타겟)
        │  (수동 큐레이션 — "베스트 1개" 선택/정제, 추정 — 미검증)
        ▼
smr_go2/new_dataset/{name}.txt  (15개, gait 이름별 대표 클립)
        │  convert_smr_to_pkl.py (완전 일치, diff=0.0)
        ▼
smr_go2_pkl/{name}.pkl  (30개 = 15 base + 15 mirror)
        │  (소폭 후처리 — 원인 미확인, diff ≤0.047)
        ▼
저장소 smr_mirror_pkl/go2_{name}.pkl  (18개 = 9 base + 9 mirror, jump류 전부 배제)
```

**즉 현행 8클립은 이 대형 데이터셋의 "curated 1-of-N 대표 샘플"이지, 전체를 다 쓴 게
아니다.** `smr_txt_retarget_dataset_go2_v0/walk/`에만 912개 raw 클립(고유 744개)이 있는데
저장소는 그중 대표 1개(`walk.txt`→`go2_walk.pkl`)만 쓰고 있다.

## 4. 커버리지 (보행 관련 카테고리만)

계산: `root_quat`에서 yaw 직접 추출 → `np.unwrap` → 시간미분 = `wz`(기존 pkl의 euler-diff
yaw-wrap 결함을 원천 회피). `v_x`는 `root_pos`를 세계좌표 유한차분 후 unwrap된 yaw로
body-frame 회전.

| 지표 | 값 |
|---|---|
| 총 프레임(중복 포함) | 247,880 |
| `v_x` 분위수 (min/p5/mean/p95/p99/max) | -2.95 / -0.05 / 0.66(가중평균) / 2.45 / 3.27 / 5.89 |
| 후진(`v_x<0`) 프레임 비율 | **11.5%** — 후진 클립 **실재** |
| `\|wz\|>1.0` 프레임 비율 | **23.3%** — 고yaw 구간 **실재** (주 출처: `spin` 카테고리, mean\|wz\|=3.51) |

| `run_walk`, `sit_trot`, `stand_trot`, `sit_run` | 고속/전이 혼합, 소량 보강용 |

3. `motion_lib.py`의 yaw-unwrap 결함(§별도 이슈, `project_amp_motion_yaw_wrap_angvel_spike` 메모리 참조)은 **이 데이터셋에도 동일하게 적용되므로 반드시 같이 수정** — 안 그러면 새 데이터의 `spin`처럼 고yaw가 많은 클립일수록 오염이 커짐
4. `jump_walk`/`run_jump` 등 혼합 카테고리는 필요 시 프레임 단위로 잘라(root z 임계값 등) 순수 gait 구간만 추출하는 후처리 검토

## 7. [2026-08-27 추가] 세션 기반 다양성 재검증 — §0/§3/§6 수치 하향 정정

**배경.** 원본 `csv_dataset_locomotion`(1,676클립)을 분석한 다른 에이전트가 파일명(`D<n>_<seq>_<subj>_<take>_F<start>_F<end>_<idx>`)을
파싱해 배후 **원 녹화 세션이 46개뿐**임을 밝혔다(walk 34, run 12, trot 6, spin 3, 전이 19).
슬라이딩 윈도우로 겹치는 구간을 촘촘히 잘라 클립 수를 부풀린 구조이며, 세션별 프레임 구간 **합집합**이
97,320프레임(~27분)으로 진짜 정보량 상한이었다. `smr_txt_retarget_dataset_go2_v0`가 같은 원본에서
파생됐는지, 같은 부풀리기가 있는지 재검증했다.

### 방법

보행 22개 카테고리(1,430파일) 전체의 파일명이 **원본과 동일한 스키마**를 그대로 유지하고 있음을 확인
(`M_` 접두사=미러, `D1_061_KAN01_001_F9308_F9633_188.txt` 형태). 정규식으로 `session=D<n>_..._<take>`,
`mirror flag`, `F<start>`, `F<end>`를 파싱(1,430개 전부 파싱 성공, 실패 0). 세션별로 `(F<start>,F<end>)`
구간을 합집합(interval union)해 "진짜 겹치지 않는 원본 정보량"을 계산했다.

계산에서는 처음부터 제외했다.**

### bin별 세션 다양성 (프레임이 아니라 "몇 개의 서로 다른 세션이 채웠나")

`v_x∈[-1,3]×8bin` × `yaw∈[-1.5,1.5]×6bin`, 값=기여 세션 수 (0=공백, non-mirror 기준):

```
vx\wz      [-1.5,-1.0) [-1.0,-0.5) [-0.5,0) [0,0.5) [0.5,1.0) [1.0,1.5]
[-1.0,-0.5)     0           0         1        1        1         1
[-0.5, 0.0)    17          19        32       31       19        15
[ 0.0, 0.5)    21          28        44       42       32        26
[ 0.5, 1.0)    18          30        39       40       30        21
[ 1.0, 1.5)     6          15        30       31       19        14
[ 1.5, 2.0)     4          14        23       23       14        11
[ 2.0, 2.5)     3           9        16       16        8         2
[ 2.5, 3.0)     2           4        13       12        6         1
```

프레임 기준으로는 48/48(100%)이 채워졌지만, **세션 기준으로 다시 보면 4칸(`v_x∈[-1.0,-0.5)`의
`wz∈[-0.5,1.5)` 3칸)은 실제로 세션 0개**다(§4의 "2프레임"짜리 칸들이 바로 이것 — 어느 세션의 찰나적
경계 프레임이 우연히 그 bin에 들어간 것이지 독립적인 후진 주행 세션이 아니다). **정정: 강한 후진
(`v_x<-1.0`) bin은 사실상 데이터가 없다.**

세션 1~2개로만 채워진 칸(과적합/클립 암기 위험 높음, `metrics/bin_session_diversity.csv` 전체 참조):

|---|---|---|
| [-1.00,-0.50) | [-0.50,0.00) | 1 |
| [-1.00,-0.50) | [0.00,0.50) | 1 |
| [-1.00,-0.50) | [0.50,1.00) | 1 |
| [-1.00,-0.50) | [1.00,1.50] | 1 |
| [2.00,2.50) | [1.00,1.50] | 2 |

회전 구간이며, 이는 `walk`(34세션) 카테고리가 지배적으로 채운 영역과 일치한다.

### 정정된 최종 판정

**여전히 Green이지만, 근거는 원 보고보다 훨씬 얇다.**

- 목표(고유 정보량 ≥10,000프레임) 대비: **49,613 / 10,000 = 4.96배** (원 보고의 18.7배가 아님)
- 논문 1(13,076) 대비: **3.80배** (원 보고와 동일하게 "충분"으로 남지만 여유는 크지 않음)
- 46세션이라는 것은 **가장 촘촘한 카테고리(walk)도 34개 원본 촬영본**에서 파생됐다는 뜻 — latent VAE
  학습 시 **세션(session, `D<n>_<seq>_<subj>_<take>`) 단위로 train/val split**하지 않으면 슬라이딩
  윈도우로 잘린 사실상 동일한 클립이 양쪽에 새어 들어가 "잘 재구성한다"는 착시(클립 정체성 암기)가
  생긴다. **md5 dedup만으로는 이 누수를 못 막는다** — 서로 다른 프레임 구간(`F630_F830` vs
  `F650_F850` 등)이라 md5가 다르지만 90% 이상 겹치는 프레임을 공유하기 때문.
- 강한 후진(`v_x<-1.0`)은 세션 0개로 **사실상 공백** — §6 권고에서 "후진 포함"이라 했던 서술은
  "약한 후진(-1.0~0)만 포함, 강한 후진은 없음"으로 정정한다.

**latent-VAE 설계에 대한 함의 (계획 문서 §Phase 1 G1/G2 게이트와 연동):**

| 권고 | 근거 |
|---|---|
| train/val split은 **세션 단위**로 (프레임/클립 단위 금지) | 46세션 기준 leave-session-out, 기존 계획의 "leave-one-clip-out"(G1)을 **leave-one-session-out**으로 강화 |
| 세션 1~2개짜리 bin은 **검증셋 전용**으로 분리하거나 별도 표시 | 그 bin의 "커버리지 100%"는 통계적으로 취약함을 학습 로그에서 구분해야 함 |
| `v_x<-1.0` 명령은 **명령 범위에서 제외**하거나 별도 합성 필요 | 실 데이터 0세션 |
| "고유 프레임" 수치를 보고할 때는 항상 **(md5-dedup 수, 세션-합집합 수)** 둘 다 병기 | 하나만 쓰면 3~4배 과장 위험 |
