## 0. 결론

**창을 넓혀도 미세 gait 판별은 살아나지 않는다. 오히려 잃는 것이 있다.**

`w` = 2 / 4 / 10 / 20, 각 **10 시드** (총 40 run) 을 학습하고 판별력을 쟀다.

| 게이트 | 목표 | w=2 (기준) | w=4 | w=10 | w=20 | 판정 |
|---|---|---|---|---|---|---|
| **D1** `legswap` / `frontswap` / `rearswap` | ≥ 0.65 | 0.519 / 0.495 / 0.521 | 0.514 / 0.503 / 0.521 | 0.507 / 0.493 / 0.522 | 0.508 / 0.498 / 0.512 | **FAIL (전 w)** |
| **D2** `desync2` / `desync5` | ≥ 0.65 | 0.507 / 0.510 | 0.507 / 0.500 | 0.502 / 0.511 | 0.508 / 0.505 | **FAIL (전 w)** |
| D3 `static` / `cat_stand` | ≥ 0.95 유지 | 1.000 / 0.986 | 1.000 / 0.988 | 1.000 / 0.992 | 1.000 / 0.991 | PASS |
| D4 `shuffle` / `speed2x` | ≥ 0.75 / ≥ 0.70 | 0.855 / 0.755 | 0.823 / 0.758 | **0.736 / 0.681** | **0.620 / 0.593** | **w≥10 회귀** |

값은 클립 단위 **배치 marginal KL** AUROC 의 10 시드 중앙값이다.
**D1·D2 는 어떤 `w` 에서도 우연 수준(0.49~0.52)을 벗어나지 않았고**, 그 사이 D4 는 무너졌다.
`w` = 20 의 `shuffle` 0.620 은 기준 `w` = 2 의 0.855 와 시드 범위가 **겹치지 않는다**
(0.595~0.650 vs 0.826~0.871).

held-out 절대 재구성도 단조 악화한다 — `val_rec` 0.00184 → 0.00392 (2.1 배),
`gap` 0.00094 → 0.00218 (2.3 배).

**왜 안 되는지도 측정했다 (§6).** 인코더는 넓어진 입력을 **거의 읽지 않는다** — 문맥 프레임을
다른 표본의 것으로 바꿔도 `z` 변화가 직전 프레임의 **10 % 이하**다. 재구성 손실이
"x[t] 로 x[t+1] 을 맞혀라" 이므로 **과거 프레임을 부호화할 유인이 손실 안에 없다.**
창을 넓히는 것은 필요조건일 수는 있어도 **충분조건이 아니다** — 손실을 함께 바꿔야 한다.

산출 코드는 남는다 — `--window_w` 는 기본 2 에서 기존 경로와 **bit-identical** 임을 확인했다(§4-1).

## 2. 설계 — 인코더만 넓히고 디코더는 한 스텝 유지

```
기존   encoder( x[t], x[t+k] )                       -> z      입력 49*2
       decoder( x[t], z )                            -> x[t+k]

변경   encoder( x[t-(w-2)k], ..., x[t-k], x[t], x[t+k] ) -> z   입력 49*w
       decoder( x[t], z )                            -> x[t+k]  그대로
```

- 문맥은 `w-1` 프레임, 표적이 1 프레임이라 인코더 입력이 정확히 `49*w` 다.
- 디코더 조건은 **문맥의 마지막 프레임 하나**(`x_ctx[:, -49:]`)다. 한 스텝 예측을 바꾸지 않는다.
- autoregressive 구간은 문맥 **롤링 버퍼**로 돈다 — 실제 프레임 `w-1` 개로 시작하고,
  매 스텝 자기 예측을 밀어 넣는다. `w` = 2 면 버퍼가 곧 직전 예측 한 프레임이라 기존과 같다.
- 정규화 통계는 프레임 단위로 tile 해 문맥 전 프레임에 **같은 mean/std** 를 건다.

클립당 표본 수는 `len - (w-1)k` 로 줄고, AR 윈도우도 앞쪽 `w-2` 프레임만큼 짧아진다.

| | w=2 | w=4 | w=10 | w=20 |
|---|---|---|---|---|
| train 전이 표본 | 45,325 | 44,215 | 40,885 | 35,389 |
| AR 윈도우 | 10,418 | 10,157 | 9,308 | 8,079 |
| 파라미터 | 684,067 | 709,155 | 784,419 | 909,859 |

## 4. 무손상 검증

### 4-1. `--window_w 2` 는 기존과 bit-identical

같은 시드로 `--window_w` 미지정 / `--window_w 2` 를 돌려 **state_dict 최대 차이 0.0**,
`train_rec`/`val_rec`/비율이 전 자리 일치. 정규화 tile 을 넣은 뒤에도 다시 확인했다.

### 4-2. 평가 하네스 — 검증 스크립트를 고치지 않고 재사용

`validate_latent_style_reward.py` 는 수정 금지이고, 그 안의
`rsl_rl.modules.motion_encoder.MotionEncoder` 는 입력이 **2 프레임 하드코딩**
(`x_dim = in_features // 2`) 이라 `w > 2` 체크포인트를 못 읽는다.

그래서 검증 스크립트를 **다시 쓰지 않고** 모듈로 로드한 뒤 심볼 두 개만 갈아끼우고
그 `main()` 을 그대로 호출하는 하네스를 새로 만들었다
(`scripts/imitation_learning/eval_window_style_reward.py`):

| 갈아끼운 것 | 내용 |
|---|---|
| `MotionEncoder` | `WindowMotionEncoder` — 입력 `w` 프레임, 정규화는 프레임 단위 tile |
| `pair_stack` | 문맥 `(w-1)` 프레임 + 표적 1 프레임 |

이렇게 하면 negative 생성·**rng 소비 순서**·통제군(`expert_train`)·raw baseline·
margKL 표본추출이 원본과 완전히 같고, raw baseline 도 자동으로 같은 `w` 프레임 창을 본다
(= "latent 가 raw 를 이겨야 한다" 는 판정 논리 유지).

**검증**: `w` = 2 에서 published 표를 **소수 셋째 자리까지 그대로 재현**한다
(`final_s2_strat` 체크포인트: shuffle 0.996 · static 1.000 · legswap 0.547 · frontswap 0.578 ·
desync2 0.536 · desync5 0.567 · cat_stand 0.977 · speed2x 0.974).

기준 `gaussfix_b0` 로 재면 팀리드 지시서의 수치와 일치한다 —
legswap 0.519 · frontswap 0.495 · desync2 0.507 · desync5 0.510 · static 1.000 ·
cat_stand 0.986 · shuffle 0.855 · speed2x 0.755. **비교 대상이 서로 다른 체크포인트임이 확인된다**
(지시서 표 = `gaussfix_b0`, Phase 2 보고서 표 = `final_s2_strat`).

### 5-2. ★ 클립집단 통제 — "긴 클립이 쉬웠던 것" 이 아니다

## 6. ★ 진단 — 인코더는 창을 거의 읽지 않는다

판별이 안 오른 이유가 (a) 인코더가 넓어진 입력을 무시해서인지 (b) 읽지만 판별에 안 쓰여서인지
가르려고, 문맥 프레임 하나를 **다른 표본의 같은 위치 프레임**으로 바꿨을 때 `z` 가 얼마나
움직이는지 쟀다 (held-out expert 20,000 쌍):

```
S_j = mean_i || z(프레임 j 만 교체) - z(원본) ||  /  mean_i || z_i - mean(z) ||
```

분모는 latent 의 자연 산포다. `S_j` ~ 0 이면 그 프레임은 `z` 에 영향이 없다.

| 교체한 프레임 | 표적 `x[t+k]` | `x[t]` | `x[t-1]` | `x[t-4]` | `x[t-9]` | `x[t-18]` |
|---|---|---|---|---|---|---|
| w=2 | 2.74 | 1.87 | — | — | — | — |
| w=4 | 2.75 | 1.84 | 0.57 | — | — | — |
| w=10 | 2.39 | 1.34 | 0.47 | 0.22 | — | — |
| w=20 | 2.22 | 1.05 | 0.43 | 0.15 | 0.12 | 0.10 |

위 표의 교란은 **다른 표본의 프레임으로 통째 교체**(`permute`)라 문맥의 연속성을 깨는 큰
변화다. "큰 변화에는 둔감하지만 작은 변화는 읽는다(포화)" 는 해석을 배제하려고, 같은 위치에
**한 프레임 차분 크기의 가우시안 잡음**만 넣는 작은 분포 안 교란(`framediff`)도 쟀다:

| 교체한 프레임 | 표적 `x[t+k]` | `x[t]` | `x[t-1]` | `x[t-4]` | `x[t-9]` | `x[t-18]` |
|---|---|---|---|---|---|---|
| w=2 | 1.01 | 0.67 | — | — | — | — |
| w=4 | 1.04 | 0.65 | 0.13 | — | — | — |
| w=10 | 0.93 | 0.50 | 0.13 | 0.05 | — | — |
| w=20 | 0.85 | 0.38 | 0.13 | 0.04 | 0.03 | 0.022 |

**작은 교란에서 비율은 오히려 더 극단적이다** — `w` = 20 에서 `x[t-18]` 은 `x[t]` 의 **5.7 %**
(`permute` 에서는 9 %). 포화 해석은 배제된다. 인코더는 과거 프레임을 **읽지 않는다**.

(두 교란 모두 3 시드에서 같다. 원자료
[`metrics/context_sensitivity.json`](metrics/context_sensitivity.json) ·
[`metrics/context_sensitivity_framediff.json`](metrics/context_sensitivity_framediff.json),
그림 [`figures/context_sensitivity.png`](figures/context_sensitivity.png))

**영향은 과거로 갈수록 지수적으로 죽는다** — 같은 `w` 안에서 `x[t-4]` 는 `x[t]` 의 **14~16 %**,
`x[t-18]` 은 **9 %** 다.
동시에 창이 넓어질수록 표적·직전 프레임의 영향 자체도 줄어(2.74 → 2.22, 1.87 → 1.05)
`z` 가 **희석**된다 — 이것이 D4(시간축 파괴 탐지)가 무너진 기전과 일치한다.

기전은 손실 함수다. 목적이 `x[t]` 로 `x[t+k]` 를 맞히는 것이므로, **과거 프레임을 `z` 에
부호화할 유인이 손실 안에 존재하지 않는다.** 정보는 입력에 들어왔지만 부호화되지 않는다.

즉 STATUS.md §3 의 진단("한 스텝 전이라 위상을 못 본다")은 **원인의 절반만 맞다**.
입력을 넓히는 것만으로는 부족하고, **위상을 담아야 이득인 목적함수**가 함께 필요하다.

## 7. 판정 요약

| # | 항목 | 목표 | 결과 | 판정 |
|---|---|---|---|---|
| D1 | `legswap`/`frontswap`/`rearswap` margKL | ≥ 0.65 | 최고 0.522 (w=10 `rearswap`) | **FAIL** |
| D2 | `desync2`/`desync5` margKL | ≥ 0.65 | 최고 0.511 | **FAIL** |
| D3 | `static`/`cat_stand` | ≥ 0.95 | 1.000 / 0.986~0.992 | PASS |
| D4 | `shuffle`/`speed2x` | ≥ 0.75 / ≥ 0.70 | w≤4 유지, **w=10 0.736/0.681 · w=20 0.620/0.593** | w≥10 **FAIL** |

**넷을 동시에 만족한 `w` 는 없다. 창 확대는 미세 gait 판별을 살리지 못한다 — FAIL.**
권고 체크포인트도 없다. Phase 2 env 는 기존 `w` = 2 인코더를 그대로 쓰는 것이 최선이다
(`w` ≥ 10 으로 바꾸면 지금 작동하는 D4 신호를 잃는다).

### 유리한 것을 고르지 않았다

`legswap` 은 검증 스크립트 docstring 과 Phase 2 보고서가 둘 다 **결함 있는 negative** 로
못박은 것이다(좌우대칭 직진보행의 좌우 교환은 반주기 상태 = 물리적으로 유효한 모션).
그래서 신호를 나르는 negative 는 `frontswap`(trot → pace) 과 `desync` 인데,
**그 둘도 0.49~0.51 로 똑같이 우연 수준**이다. 결함 negative 를 빼도 결론은 바뀌지 않는다.

## 8. 재현

```bash
R=reports/go2_imitation/go2_imitation_tracking/2026-08-28_window_encoder

# 스윕 (40 run, GPU 1 기준 train 12 s + eval 9 s 각)
SP=/원하는/작업경로 bash $R/sweep.sh
SP=/원하는/작업경로 bash $R/followup.sh     # 통제 + eval 시드

# 단일 학습 (w=10, 시드 0)
python scripts/imitation_learning/train_go2_motion_vae.py --out_dir <OUT> \
  --latent_dist gauss --gauss_fixed_logvar -4.0 --beta 0.0 --stride 2 --latent_dim 18 \
  --window_w 10 --seed 0

# 판별력 (창 하네스 — 검증 스크립트는 읽기 전용으로 호출된다)
python scripts/imitation_learning/eval_window_style_reward.py --ckpt <OUT>/motion_vae.pt \
  --out_dir <EVAL_OUT> --device cuda:0 --seed 0
#   --min_clip_len 83  을 주면 w=20 의 클립 집단으로 통제 비교

# 집계 · 그림 · 진단
python $R/aggregate.py --sweep_dir <SWEEP>/sweep --out_dir $R/metrics
python $R/make_figures.py
python $R/context_sensitivity.py --perturb permute   --ckpts <...> --out_json $R/metrics/context_sensitivity.json

python $R/gait_separability.py --ckpts <...> --out_json $R/metrics/gait_separability.json
```

★ `eval_window_style_reward.py` 는 `--out_dir` 을 반드시 명시한다. 기본값이
`2026-08-27_phase2_style_reward_validation` 이라 그냥 돌리면 published metrics 를 덮어쓴다.

체크포인트 40 개(3~4 MB × 40)는 세션 scratchpad 에만 있고 보고서에는 싣지 않았다.
FAIL 이라 승계할 체크포인트가 없기 때문이다. 위 명령으로 12 초에 재생성된다.

## 9. 다음에 시도할 만한 것 (제안 — 착수하지 않았다)

§6 이 가리키는 방향은 하나다 — **위상을 담는 것이 이득이 되는 목적함수**.

| 안 | 내용 | 근거 |
|---|---|---|
| A | 창 인코더 + **`predict_ahead` 확대** (k = 5~10) | 한 스텝이면 `x[t]` 만으로 결정되지만, 0.2 s 뒤를 맞히려면 위상이 필요하다. 창은 이미 구현됐고 `k` 는 기존 플래그다. ★**다중스텝 단독은 STATUS.md §1-3 에서 1.2 % 로 약했다** — 미시도인 것은 창과 **함께** 주는 조합이다 |
| B | 창 인코더 + **다중 스텝 표적** (`z` 하나로 향후 n 프레임 재구성) | 같은 논리를 롤아웃 전체에 건다. AR 경로가 이미 있다 |
| C | 대조 학습 목적 (같은 클립의 다른 시점 = positive, `frontswap`/`desync` = 부정) | 판별 자체를 목적에 넣는다. 다만 negative 설계가 게이트와 순환할 위험 |

**A 를 먼저 볼 것을 권한다** — 코드 변경이 0 이고 (플래그 두 개), §6 의 기전을 직접 겨냥한다.
단, `k` 를 바꾸면 예측 지평이 달라져 `val_rec` 을 `w` 스윕과 **비교할 수 없다**
(`gaussfix_reg/README.md` 가 못박은 제약).

### 착수하지 않을 것

| 항목 | 사유 |
|---|---|
| `w` 를 20 보다 더 키우기 | `S_j` 가 이미 0.10 이다. 더 넣어도 안 읽는다 |
| 창 + 인코더 용량 확대 | 문제는 용량이 아니라 유인이다(`train_rec` 도 함께 올랐다) |
