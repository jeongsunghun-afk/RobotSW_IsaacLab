## 결론

**트레이드오프는 깨지지 않았다 — FAIL.**

미시도 축 6 종(인코더 입력 잡음 · 디코더 조건 잡음 · 인코더 dropout · 디코더 dropout ·
weight decay · 학습량 축소)을 강도별로 25 설정, 총 **173 run** (고유 설정x시드) 돌렸다. 결과는 두 갈래로 갈리고
가운데가 없다.

| | `G1 <= 2.0` 을 안정적으로 달성 | `val_rec` 허용선(+20%) 안 |
|---|---|---|
| 잡음·학습량 축소 (`ne`, `nd`, `dd`, `ar`) | **O** | X (+37% ~ +156%) |
| weight decay (`wd`, `ewd`) | X | **O** (−3% ~ +3%) |
| 인코더 dropout (`de`) | X | O — 그러나 **walk 효과가 21.6% → 10.9%(p 0.05) → 3.6%(p 0.20) 로 지워진다** |

**허용선 안에 있는 arm 중 기준선의 `PASS 2/10` 을 넘은 것은 하나도 없다** (0/10 ~ 2/10).
`G1` 을 확실히 내리는 arm 은 전부 `val_rec` 을 함께 올린다 — 즉 **모델을 망가뜨려 비율 게이트를
통과한 것**이고, 팀리드 지시서의 판정 함정 2번이 정확히 이 경우를 금지한다.

### 그러나 더 중요한 발견 두 가지가 나왔다

**(1) `G1` 게이트 자체가 이 비교에 부적합하다 (§6).**
`G1` 은 비율이라 **오차 바닥을 올리는 것만으로 통과할 수 있다.** `ar10` 은 `G1` 을 1.57 로
내려 **10/10 통과**하지만 `val_rec` 이 2.6 배 나빠진 대가다. 반대로 `gaussfix_b0` 는
**같은 예측 지평(stride 2, k 1)의 설정 중** held-out 절대 오차 `val_rec` 0.00184 와
일반화 격차 `gap` 0.00094 가 **최소**인데 (게이트를 통과한 `regress_gauss` 의 `gap` 의 **1/11**)
`G1` 만으로 탈락한다.
**"`gaussfix_b0` 는 일반화가 나쁘다"가 아니라 "in-sample 이 유난히 좋다"가 맞는 서술이다.**

**(2) 판정에 쓰인 두 수치가 모두 측정 잡음 안에 있다 (§3-3, §7).**

```
G1        기준선 10 시드 : 2.04 [1.84 ~ 2.23]     목표 마진 2.01 -> 2.00 = 0.01
전이 ->run 기준선 10 시드 : +0.72 [-0.41 ~ +0.95]   목표 기준 +0.5
```

상위 보고서의 `G1 = 2.01` 과 `->run = +0.90` 은 **3 시드 중앙값**이었다. 10 시드로 재면
`G1` 은 시드만 바꿔도 1.84 까지 내려가고, 전이 상관은 **10 시드 중 3 개에서 +0.5 미만**이다.
"`gaussfix_b0` 만 유일하게 전역 속도축을 갖는다" 는 전제는 **10 시드 중 7 개의 진술**이다.

## 2. 기호

### 2-1. 정규화 축 (본 세션에서 추가한 것)

| 플래그 | 뜻 | 단위 |
|---|---|---|
| `--noise_enc` | **인코더 입력** `(x_prev, x_curr)` 에 더하는 가우시안 잡음의 sigma | 정규화 공간 std |
| `--noise_dec` | **디코더 조건** `x_prev` 에만 더하는 잡음 sigma. 표적은 언제나 원본 | 정규화 공간 std |
| `--dropout_enc` | 인코더 은닉층 dropout 확률 | `[0, 1)` |
| `--dropout_dec` | 디코더 expert 은닉층 dropout 확률 | `[0, 1)` |
| `--weight_decay` | AdamW decoupled weight decay (전 파라미터) | — |
| `--enc_weight_decay` | 인코더에만 거는 weight decay (나머지는 `--weight_decay`) | — |
| `--epochs_ar` | autoregressive 구간 epoch 수 (기본 60). 줄이면 학습량 자체가 준다 | — |

### 2-2. 지표 (상위 보고서와 동일 정의)

| 기호 | 정의 | 기준 |
|---|---|---|
| `G1` | held-out **세션** 재구성 MSE / in-sample MSE (**비율**) | `<= 2.0` |
| `val_rec` | held-out 세션 재구성 MSE 절대값 (정규화 공간, 차원당) | 기준선 0.00184 |
| `train_rec` | in-sample 재구성 MSE 절대값 | 기준선 0.00090 |
| `gap` | `val_rec - train_rec`. 일반화 격차의 **절대** 크기 | 작을수록 좋다 |
| `walk 효과` | `G2b` — (보간 시 예측 vx 변화폭) / (클립 A·B 평균속도 차) 의 중앙값 | `>= 10%` |
| `walk R^2` | `G2a` — 선형 프로브 `z -> 클립 평균 vx`, LOO 교차검증 | `>= 0.5` |
| `->run`, `->trot` | **walk 121 클립으로만** 적합한 `z -> vx` 프로브를 run/trot 에 적용한 상관 | `>= +0.5` |
| `PASS` | 위 다섯을 **한 시드 안에서 동시에** 만족한 시드 수 / 전체 시드 수 | — |

`PASS` 규약은 상위 보고서 `gate_table.txt` 와 같다 — 중앙값이 기준을 넘어도 시드가 걸치면 통과가 아니다.

### 2-3. 사전에 못 박은 허용선

정규화는 예외 없이 `val_rec` 을 조금 올린다. "오르면 개선이 아니다"로 읽으면 만족 불가능한 기준이 되므로,
**결과를 보기 전에** 다음을 선언하고 그대로 적용했다.

```
val_rec 증가 20% 이내  ->  허용 (기준선 0.00184 -> 0.00221 까지)
val_rec 증가 20% 초과  ->  FAIL. G1 이 내려가도 개선으로 치지 않는다
```

`G1` 은 비율이라 단독으로 못 믿는다 (상위 §11-4 의 `bal-sess` 가 G1 1.66 인데 `val_rec` +9.7% 였다).
그래서 전 arm 의 `train_rec` / `val_rec` / `gap` 을 **셋 다** 싣는다.
진짜 판별점은 **gap 이 줄었는가**이지 G1 이 내려갔는가가 아니다.

## 3. 방법

### 3-1. 사본과 재현 검증

`train_go2_motion_vae.py` / `eval_go2_motion_vae.py` 는 다른 워커가 수정 중이라 건드리지 않았다.
사본 `_exp_train_vae_reg.py` / `_exp_eval_vae_reg.py` 를 만들고 **정규화 옵션만** 추가했다.
전부 기본값 0 이라 옵션을 안 주면 원본과 같은 코드 경로를 탄다.

- dropout 은 `nn.Dropout` 모듈이 아니라 **functional** 로 걸었다. `nn.Sequential` 에 모듈을 끼우면
  `encoder.0/2/4` 인덱스가 밀려 기존 체크포인트와 `state_dict` 이름이 어긋난다.
- 평가 사본은 모델 정의를 **본 세션 사본에서** import 한다. 원본이 바뀌면 체크포인트 로드가
  깨지는 유일한 경로라 끊어 뒀다.

**재현 검증** — `gaussfix_b0` 설정을 사본으로 다시 돌려 `G1` 이 소수 셋째 자리까지 일치했다.

| 시드 | 기존 `vmf/gaussfix_b0_s*` | 사본 `runs/repro_s*` |
|---|---|---|
| 0 | 2.218 | **2.218** |
| 1 | 2.008 | **2.008** |
| 2 | 1.899 | **1.899** |

전이 상관 하네스([`sweep.py`](sweep.py) 의 `transfer_corr`)도 원본 `vmf/axis_alignment.py` 를
재구현한 것이라 같은 3 시드에서 상위 보고서와 대조했다.

| | 상위 보고서 `gaussfix_b0` (3 시드) | 본 세션 `base` s0/s1/s2 |
|---|---|---|
| →run | +0.90 [−0.22~+0.95] | +0.95, −0.22, +0.90 → **+0.90 [−0.22~+0.95]** |
| →trot | +0.94 [+0.57~+0.95] | +0.94, +0.57, +0.95 → **+0.94 [+0.57~+0.95]** |

**완전히 일치한다.** 따라서 아래 arm 들은 기존 수치와 직접 비교할 수 있고,
§7 의 "10 시드로 재면 +0.72" 는 하네스 차이가 아니라 시드 산포다.

### 3-2. 잡음을 표적에 넣지 않는 이유

`x_curr` 는 인코더 입력이면서 **디코더의 재구성 표적**이다. 표적에 sigma 를 더하면 MSE 의
하한이 sigma^2 만큼 올라 `val_rec` 이 기준선 0.00184 와 나란히 놓을 수 없게 된다.

```
--noise_enc : 인코더가 보는 (x_prev, x_curr) 사본에만 더한다
--noise_dec : 디코더 조건 x_prev 에만 더한다
표적        : 언제나 원본. 손실 F.mse_loss(xh, b) 의 b 는 깨끗하다
```

주입은 `self.training` 게이트 안에 있다 — eval 로 새면 `G1` 이 조용히 오염된다.

### 3-3. 시드 수를 10 으로 올린 이유 (★ 이번 세션의 첫 발견)

`gaussfix_b0` 의 `G1` 은 시드만 바꿔도 **1.84 ~ 2.23** 으로 흔들린다 (10 시드).
같은 run 안에서도 마지막 4 개 기록 에폭의 비율이 1.92 ~ 2.22 로 움직인다.

```
목표 마진 : 2.01 -> 2.00   =  0.01
측정 산포 : 시드 간 0.39,  에폭 간 0.30
```

**목표 마진이 측정 잡음의 1/30 이다.** 3 시드 중앙값으로는 어떤 정규화도 판정할 수 없다 —
아무 것도 하지 않아도 시드를 뽑으면 1.84 가 나온다. 그래서

- 기준선을 **10 시드**로 다시 재고,
- 판정은 중앙값이 아니라 상위 보고서 규약인 **`PASS k/n`** (시드별 전 게이트 동시 통과 수) 으로 한다.

이 사실 자체가 팀리드에게 필요한 정보다 — 상위 §2 의 "`gaussfix_b0` 는 G1 2.01 로 탈락,
2.01 을 2.0 으로 반올림하지 않는다" 는 판정은 **잡음 안에 있는 판정**이었다.
(단 `G1` 의 정의는 바꾸지 않았다. 마지막 에폭 값 그대로이고 산포를 함께 싣는다.)

### 4-1. 축마다 무슨 일이 일어나는가

**(a) 인코더 입력 잡음 (`ne`) · 디코더 조건 잡음 (`nd`) · 학습량 축소 (`ar`) — G1 은 내려가지만 값을 치른다.**
강도를 올리면 `G1` 이 단조 감소하고 `val_rec` 이 단조 증가한다. 예외 없다.
`G1 <= 2.0` 을 안정적으로 얻는 지점은 전부 `val_rec` 허용선 밖이다.

**(b) dropout — `G1` 은 거의 안 움직이고 속도축이 지워진다.**
인코더 dropout 은 강도를 올려도 `G1` 이 2.20 → 2.10 으로 거의 그대로인데
**walk 효과가 22% → 11% → 7.3% → 3.6% 로 무너진다.** 팀리드 지시서 함정 1번이 말한
"축이 고쳐진 것이 아니라 지워진 것"의 교과서적 사례다 — 전이 상관은 +0.93~+0.98 로
오히려 좋아 보이지만 조종할 축 자체가 없다. 디코더 dropout 은 `G1` 을 내리지만
효과가 정확히 10% 선에 걸려 시드마다 통과·탈락이 갈린다.

**(c) weight decay — 유일하게 `val_rec` 을 올리지 않지만 `G1` 도 안 내린다.**
`ewd0.30` 은 `val_rec` −8%, `gap` 0.00092 로 **전 arm 중 유일하게 기준선보다 작은 gap** 이다.
walk 효과도 24.1% 로 온전하다. 그런데 `G1` 중앙값은 2.21 로 기준선보다 **나쁘다**.
in-sample 이 함께 좋아지기 때문이다 (`train_rec` 0.00090 → 0.00084, 10 시드).

**(d) 조합은 단독의 합보다 낫지 않다.** `ne05wd10`, `ne05de10`, `ne05ar30` 모두

## 6. ★ 왜 `G1` 은 내려가는데 개선이 아닌가 — 비율 게이트의 구조적 결함

`--noise_enc` 강도를 올리면 `G1` 이 **단조 감소**한다: 2.13 → 2.04 → 1.88 → 1.74 → 1.67.
목표만 보면 성공이다. 그런데 같은 축에서 `val_rec` 은 **단조 증가**한다: 0.00174 → 0.01010 (5.8배).

```
G1 = val_rec / train_rec

정규화를 걸면 두 항이 **함께** 오른다. 그런데 train_rec 이 더 빨리 오르므로 비율은 내려간다.
  base    : 0.00184 / 0.00090 = 2.04
  ne0.40  : 0.01010 / 0.00605 = 1.67   <- "통과"지만 모델은 5.5배 나빠졌다

일반화 격차의 **절대** 크기 gap = val_rec - train_rec 은 반대로 움직인다:
  base 0.00094 -> ne0.10 0.00133 -> ne0.20 0.00222 -> ne0.40 0.00405   (+331%)
```

즉 **비율 게이트 `G1 <= 2.0` 은 모델을 망가뜨리는 것으로 통과할 수 있다.**
상위 §11-4 가 `bal-sess`(G1 1.66, `val_rec` +9.7%)에서 같은 함정을 지적했는데,
정규화 축에서는 그 효과가 훨씬 크다.

이것이 본 세션의 핵심 결론이다 — **`gaussfix_b0` 의 G1 2.01 은 "일반화가 나쁘다"가 아니라
"in-sample 이 유난히 좋다"의 다른 표현이다.** `val_rec` 0.00184 는 vMF 계열 `pa3_vmf10`
(0.06673) 의 **1/36** 이다. 분자가 아니라 분모가 작아서 비율이 큰 것이다.

**★ 지평을 맞춘 비교만 유효하다.** `val_rec` 의 크기는 일반화가 아니라 **예측 지평**이 지배한다
(`stride`·`predict_ahead` 가 다르면 아예 다른 문제를 푸는 것이다). 상위 §11-4 가 못 박은 대로
`val_rec` 은 **같은 `stride`·`predict_ahead` 안에서만** arm 간 직접 비교가 된다.

`gaussfix_b0` 는 `stride 2 / k 1` 이다. 같은 지평의 설정만 남기면:

| 설정 | stride / k | `train_rec` | `val_rec` | gap | `G1` | 판정 |
|---|---|---|---|---|---|---|
| `regress_gauss` (기존 기준선) | 2 / 1 | 0.01714 | 0.02708 | 0.00994 | 1.580 | PASS |
| `vmf_k10` | 2 / 1 | 0.01144 | 0.01726 | 0.00583 | 1.509 | PASS |
| **`gaussfix_b0`** (β=0, 10 시드 중앙값) | 2 / 1 | 0.00090 | **0.00184** | **0.00094** | 2.04 | **FAIL** |
| ~~`pa3_vmf10`~~ (권고 설정) | 2 / **3** | 0.03780 | 0.06673 | 0.02893 | 1.765 | PASS |
| ~~`st1_pa3_vmf10_s0`~~ (권고 설정) | **1** / **3** | 0.01402 | 0.02701 | 0.01298 | 1.926 | PASS |

(아래 두 행은 지평이 달라 `val_rec` 을 직접 비교할 수 없다. 참고로만 싣는다 —
같은 k=3 인데 stride 만 다른 두 행이 2.5 배 차이 나는 것이 지평 지배의 증거다.)

**같은 지평(stride 2, k 1) 안에서 `gaussfix_b0` 의 held-out 절대 오차는 `regress_gauss` 의 1/15,
`vmf_k10` 의 1/9 이고 `gap` 은 각각 1/11, 1/6 이다.** 즉 세 설정 중 held-out 예측이 가장 정확하고
일반화 격차도 가장 작은데, `G1` 만으로 유일하게 탈락한다. 게이트가 재는 것은 일반화가 아니라
**in-sample 이 held-out 보다 얼마나 유난히 좋은가**다.

## 7. ★ 두 번째 잡음 발견 — 전이 상관도 3 시드로는 못 믿는다

상위 보고서는 `gaussfix_b0` 의 walk 프로브 전이 상관을 **+0.90 [−0.22~+0.95] (3 시드)** 로 싣고,
"β=0 Gaussian 계열만 유일하게 전역 속도축을 갖는다" 는 결론의 근거로 삼았다.
같은 설정을 10 시드로 재면:

```
->run   +0.72 [-0.41 ~ +0.95]     10 시드 중 +0.5 이상은  7 개
->trot  +0.78 [+0.54 ~ +0.98]     10 시드 중 +0.5 이상은 10 개
둘 다 +0.5 이상                    10 시드 중             7 개
```

시드별 `->run` 값: −0.41, −0.22, −0.20, +0.53, +0.65, +0.79, +0.85, +0.90, +0.94, +0.95.
**3 개 시드는 축이 아예 뒤집힌다.** `->trot` 은 10/10 이 양수이므로 방향 자체는 실재하지만,
`run` 쪽은 시드 뽑기다.

기준선 10 시드의 게이트별 통과 수:

| 조건 | 통과 시드 |
|---|---|
| walk 효과 >= 10% | **10/10** |
| walk `G2a` R^2 >= 0.5 | **10/10** |
| `->trot` >= +0.5 | **10/10** |
| `->run` >= +0.5 | 7/10 |
| `G1` <= 2.0 | **3/10** |
| 다섯 동시 | **2/10** |

**`gaussfix_b0` 의 실제 결격 사유는 두 개다** — `G1`(3/10) 과 `->run`(7/10).
상위 보고서는 앞의 것만 지적했다.

실무적 함의: `gaussfix_b0` 를 Phase 2 로 넘긴다면 **시드를 골라야 한다.**
10 시드 중 다섯 조건을 모두 만족하는 시드가 2 개 있다 (s2: `G1` 1.899 / `->run` +0.90 / 효과 20.7%,
s9: `G1` 1.835 / `->run` +0.85 / 효과 24.9%). 정규화로 분포를 옮기는 데는 실패했지만,
**분포 안에 이미 쓸 만한 표본이 있다.**

**★ 단, 이것은 누수다.** held-out 세션으로 잰 `G1` 으로 시드를 고르는 것은
본 세션이 §3-2 에서 거부한 "val 세션 기준 early stopping" 과 **정확히 같은 종류의 누수**다
(게이트를 직접 최적화한 값이 된다). 그래서 조기 종료를 정직한 형태로만 시험했듯,
시드 선별도 **"선별했다"를 명시하지 않고는 쓸 수 없다.** Phase 2 에서 그 체크포인트가
좋다는 보장도 아니다 — `G1` 은 재구성 비율일 뿐 정책 성능이 아니다.

## 9. 권고

**(1) `G1` 게이트를 절대 지표로 바꿔라.** §4 가 보인 대로 비율 게이트는 모델을 망가뜨려
통과할 수 있고 (`ar10` 이 10/10 통과), 반대로 연구 전체에서 held-out 오차가 가장 작은 모델을
탈락시킨다. 세션 일반화를 재고 싶다면

```
현행 : val_rec / train_rec <= 2.0            <- 오차 바닥을 올리면 통과된다
대안 : val_rec <= (기준 모델의 val_rec) x C   <- 절대 성능. 설정 간 직접 비교 가능
   또는 gap = val_rec - train_rec 을 함께 게이트
```

`pa3_vmf10`(현 권고 설정)의 `val_rec` 은 0.06673 으로 `gaussfix_b0` 의 **36 배**다.
현행 게이트는 이 사실을 못 본다.

**(2) 정규화 축은 소진됐다.** 6 축 x 강도 x 조합에서 새 정보가 나오지 않는다.
상위 §7-2 의 남은 후보인 **속도축 정렬 손실**과 **속도 조건부 인코더**로 가는 것이 맞다
(원본 스크립트에 다른 워커가 이미 `--lambda_speed` / `speed_head` 를 넣고 있다).

**(3) 시드 수를 늘려라 — 비용이 없다.** 한 run 이 20 초다. 3 시드 판정은
`G1`(산포 0.39)에서도 전이 상관(산포 1.36)에서도 뒤집힌다. 이 실험군에서 **최소 10 시드**를 권한다.

```bash
cd $R && $PY sweep.py --spec spec_screen.json --seeds 3 --out metrics/screen.json
$PY summarize.py metrics/*.json          # arm 집계표
$PY gate_table.py metrics/*.json         # 시드별 게이트 분해
$PY _tradeoff.py metrics/*.json          # G1 하락 대 val_rec 상승 궤적
```

한 run 은 학습 ~13 s + 게이트 3 종 ~7 s 다. 시드 10 개짜리 arm 이 4 분이면 끝나므로
**이 실험군에서 시드 수를 아끼는 것은 이득이 없다.**
