## 결론

Gaussian posterior collapse 는 **해소됐다.** 보간 효과크기가 0.1% → 23.3% 로 올랐고 `walk` 게이트를
5/5 시드로 통과한다. 그러나 **latent 의 속도축이 gait 카테고리마다 따로 놀고, `run`/`trot` 에서는
방향이 뒤집힌다.** 즉 산출물은 **저속(walk) 영역에 한정된 latent** 이고,
Phase 2 가 요구하는 "전 속도역을 일관되게 조종할 수 있는 latent" 은 아직 없다.

| | 판정 |
|---|---|
| **G1 / G2a / G2b (walk)** | **PASS** — `pa3_vmf10` 5/5, `st1_pa3_vmf10` 5/5 |
| **속도축의 카테고리 간 일관성** | **FAIL** — walk 로 적합한 속도 프로브의 `trot` 전이 상관 **−0.82 [−0.94~−0.65], 5/5 시드** |
| **G2b (run)** | **FAIL** — vMF 설정 **37/37 run 에서 rho 음수** (완전 재현) |

**Phase 2 는 이 latent 을 저속 전용으로만 쓸 수 있다.** 그린라이트가 아니다.

## 1. 기호

### 1-1. 분포·모델

| 기호 | 뜻 | 단위/범위 |
|---|---|---|
| `d` | latent 차원 (ambient). z 는 `S^(d-1)` 위 | 기본 18 |
| `mu` | vMF 평균 방향, `||mu|| = 1` | — |
| `kappa` | vMF 집중도. 클수록 mu 주변에 몰린다 | `> 0` |
| `m` | `= d - 1`. rejection sampler 의 Beta/로그항 차수 | — |
| `A_d(k)` | `I_(d/2)(k) / I_(d/2-1)(k)` = `E[z·mu]` | `[0, 1)` |
| `I_v` | 제1종 변형 베셀 함수. log 스케일로만 다룬다 | — |
| `sigma` | Gaussian latent 표준편차 (`exp(0.5·logvar)`) | — |
| `beta` | KL 가중치 | 논문 값 0.05 |
| `k` | `--predict_ahead`. 디코더가 `x[t] -> x[t+k]` 를 예측 | 1, 3, 5, 10 |
| `stride` | 모션 서브샘플. 1 = 60fps, 2 = 30fps | 1, 2 |

vMF KL 닫힌형 (균등 prior 기준, Davidson et al. 2018):

```
KL( vMF(mu,k) || U(S^(d-1)) ) = k * A_d(k) + log C_d(k) + log S_(d-1)

log C_d(k)  = (d/2 - 1) * log k  -  (d/2) * log(2*pi)  -  log I_(d/2-1)(k)
log S_(d-1) = log 2  +  (d/2) * log pi  -  lgamma(d/2)
```

`kappa` 를 상수로 고정하면 이 값 전체가 방향 `mu` 에 무관한 상수가 되어 gradient 가 0 이다.
그래서 `--kappa_fixed` 경로에서는 KL 항을 손실에서 **아예 뺐다**. 이것이 "붕괴 압력 0" 가설을
나르는 변형이다.

### 1-2. 게이트·진단 지표

| 기호 | 정의 | 기준 |
|---|---|---|
| `G1` | held-out **세션** 재구성 MSE / in-sample MSE | `<= 2.0` |
| `G2a` | 선형 프로브 `z -> 클립 평균 vx`, LOO 교차검증 `R^2` | `>= 0.5` |
| `G2b` | `(보간 시 예측 vx 변화폭) / (클립 A·B 평균속도 차)` 의 중앙값 | `>= 10%` |

## 3. 핵심 발견 — 팀리드의 해석은 절반만 맞다 (기여도가 비대칭이다)

팀리드는 "vMF 단독도, 다중스텝 단독도 안 되고 둘의 조합만 통과한다"고 읽었다.
**조합이 필요한 것은 맞지만 두 요인의 기여는 대등하지 않다.**

| 요인 | 설정 | 효과크기 | PASS |
|---|---|---|---|
| 둘 다 없음 | `regress_gauss` | 0.1% | 0/1 |
| **다중스텝 단독** | `pa3_gauss` | **1.2%** | **0/3** |
| **vMF 단독** | `vmf_k10` | **12.0%** | **4/5** |
| 둘 다 | `pa3_vmf10` | 23.3% | 5/5 |

- **다중스텝 단독은 아무 것도 하지 않는다** — 0.1% → 1.2%. k=5, k=10 으로 늘려도 0.8~0.9% 다.
- **vMF 단독이 일을 거의 다 한다** — 0.1% → 12.0%, 약 100배. 다만 최악 시드 8.1% 로 기준을 걸쳐 4/5.
- 다중스텝은 **이미 존재하는 효과를 대략 2배로 키워** 5/5 로 만든다.

### 왜 조합이어야 하는가

`x[t]` 가 `x[t-1]` 로부터 거의 결정적이라는 것이 원래 문제였다 (상위 보고서 §2).
두 처방은 **서로 다른 병목**을 푼다.

```
병목 1 (분포)   : z 가 잡음에 묻혀 디코더가 읽을 가치가 없다
                  Gaussian 은 free_bits 0.02 하한 때문에 |mu| <~ 0.2 인데 sigma ~ 1
                  -> z 의 SNR 이 0.2. 디코더가 무시한 것은 올바른 행동이었다
                  vMF 고정 kappa=10 이면 z 는 단위벡터 + 각도퍼짐 ~1/sqrt(10)
                  -> z 가 거의 결정적인 코드가 된다.  이것이 12.0% 를 만든다

병목 2 (과제)   : x[t-1] 만으로 x[t] 가 결정되면 z 를 읽을 **이유**가 없다
                  k=3 이면 100ms 뒤를 맞춰야 해서 x[t-1] 만으로는 부족해진다
                  -> z 가 필요해진다.  이것이 12.0% 를 23.3% 로 만든다
```

병목 1 을 안 풀면 z 가 읽을 가치가 없으므로 병목 2 를 풀어도 소용없다 (`pa3_gauss` 1.2%).
병목 2 를 안 풀면 z 를 읽을 이유가 부족해 효과가 기준에 걸친다 (`vmf_k10` 4/5).

### 이 이득이 "디코더가 z 에 더 기댄 것"의 부산물이 아니라는 증거

`G0`(z 셔플)와 `G1` 은 전 설정에서 함께 움직인다 — 디코더가 z 에 기댈수록 일반화가 나빠진다.

| 설정 | G0 셔플 | G1 | walk 효과 |
|---|---|---|---|
| `regress_gauss` | 1.05 | 1.58 | 0.1% |
| `vmf_k10` | 2.14 | 1.52 | 12.0% |
| `vmf_k20` | 3.45 | 1.63 | 4.5% |
| `vmf_k50` | 5.91 | 1.63 | 3.3% |
| `vmf_klearn` | 16.12 | 1.92 | 3.2% |
| `gaussfix_b0` | 92.48 | 2.01 | 22.5% |
| **`pa3_vmf10`** | **1.89** | 1.77 | **23.3%** |

`pa3_vmf10` 은 이 곡선 **밖**에 있다. G0 1.89 로 `vmf_k10`(2.14)과 사실상 같은 z 의존도인데
효과는 2배다. 즉 "지평을 늘려서 디코더가 z 에 더 기대게 됐다"로는 설명되지 않는다.
반대쪽 대조군 `pa3_gauss`(1.2%)가 "지평이 분자를 기계적으로 부풀렸다"도 배제한다.

## 4. κ 의 역할 — 클수록 좋지 않다

효과크기는 κ=10 을 정점으로 꺾인다.

| κ | E[z·mu] | KL (상수) | G0 셔플 | G1 | walk 효과 |
|---|---|---|---|---|---|
| 5 | 0.261 | 0.63 | 1.59 | 1.47 | 2.5% |
| **10** | **0.451** | **2.02** | **2.14** | **1.52** | **12.0%** |
| 20 | 0.655 | 4.95 | 3.45 | 1.63 | 4.5% |
| 50 | 0.843 | — | 5.91 | 1.63 | 3.3% |
| 100 | 0.918 | — | 10.66 | 1.87 | 3.0% |
| 학습 | — | — | 16.12 | 1.92 | 3.2% |

`G0` 는 κ 에 대해 **단조 증가**한다 (1.59 → 16.12). 즉 κ 를 올릴수록 디코더는 z 에 더 의존한다.
그런데 **조종 가능성은 오히려 떨어진다.** 두 지표가 다른 것을 재고 있다.

기전 — κ 가 커지면 사후분포 `q(z|x[t-1], x[t])` 가 뾰족해져 **전이 하나에 z 하나가 거의 일대일로 붙는다.**
그러면 z 는 "다음에 무엇을 할지"(제어 신호)가 아니라 **"이 전이가 데이터셋의 어느 것인지"(상태 지문)** 가 된다.
지문은 재구성에는 최고의 정보라 `G0` 를 끌어올리지만, 지문 사이를 보간해도 의미 있는 중간 동작이
나오지 않으므로 `G2b` 는 떨어진다. `G1` 도 함께 나빠지는 것(1.47 → 1.92)이 같은 이야기다.

κ 가 너무 작으면(κ=5, `E[z·mu]`=0.26) 반대로 원래의 SNR 문제로 되돌아간다 — 효과 2.5%, rho +0.36.
**κ=10 (`E[z·mu]` ≈ 0.45) 이 그 사이의 최적점**이고, 18-D 에서 이 값은 각도 퍼짐 `~1/sqrt(10)` 에 해당한다.

## 5. `gaussfix_b0` — 무엇을 바꿨고 왜 탈락인가

```
--gauss_fixed_logvar -4.0   logvar 를 상수 -4 로 고정 (sigma = 0.135)
--beta 0.0                  KL 항을 손실에서 제거
```

이 설정의 목적은 **대조군**이었다. `--kappa_fixed` vMF 는 KL 을 아예 빼는데
`--gauss_fixed_logvar` 단독 설정은 KL 압력이 살아 있었기 때문이다 — 조건을 맞추지 않으면
"기하 때문인가 SNR 때문인가"를 가를 수 없다. 실제로 `logvar = -4` 에서는

```
차원당 KL = 0.5*mu^2 + 0.5*(exp(-4) + 3) ~= 0.5*mu^2 + 1.51
```

로 free_bits 0.02 를 훨씬 넘어 clamp 가 걸리지 않는다. 즉 `beta=0.05` 가 `|mu|` 에
**실제 수축 압력**을 주고 있었다. 그래서 `gauss_fixlv-4` 는 효과 0.7% 에 머물렀고,
`beta=0` 을 주자 22.5% 로 뛴다.

**해석의 정정** — 팀리드 지시서와 상위 보고서는 "z 가 단위벡터라 무시할 수 없다"를 vMF 의
기전으로 들었다. 이건 **틀렸다.** 디코더는 `||z||` 와 무관하게 첫 레이어의 z 슬라이스 가중치를
0 으로 만들 수 있다. `gaussfix_b0` 가 구(球) 없이도 22.5% 를 내는 것이 반증이다.
실제로 작동한 축은 **"KL 압력 제거 + 낮은 잡음"** 이고, `--kappa_fixed` vMF 는 그것을 공짜로 얻는다.

### 왜 일반화가 무너지는가

`beta=0` 이면 latent 에 아무 정규화가 없다. encoder 는 재구성에만 최적화되어
**train 전이를 최대한 구분하는 부호**를 만든다.

| | r_enc (val) | x_prev 셔플 | z 셔플 | G1 |
|---|---|---|---|---|
| `regress_gauss` | 0.02708 | 67.2× | 1.05× | 1.58 |
| `pa3_vmf10` | 0.06673 | 25.7× | 1.89× | 1.77 |
| `gaussfix_b0_s0` | **0.00175** | 864× | **97.4×** | 2.01 |

`gaussfix_b0` 는 재구성 오차가 다른 설정의 **1/15** 다. `x_prev` 도 여전히 쓰고 있으므로
(셔플 864×) 논문의 상태전이 VAE 구조가 무너진 것은 아니다. 문제는 그 정밀도를 **train 세션에
특화된 부호**로 달성했다는 것이고, 그래서 held-out 세션에서 G1 = 2.01 로 기준을 넘는다.

용량·잡음을 줄여 G1 을 낮추면 효과가 같이 사라진다. **정면 트레이드오프**다.

## 6. ★ 부호 반전 — 실재하며, 통과 설정의 실패 항목이다

`walk` 는 rho +1.00 인데 `run`/`trot` 은 음수라는 팀리드의 지적을 전수 조사했다.
**지적이 맞다. 게이트를 통과한 설정들의 실패다.**

### 6-1. 재현성 — 잡음이 아니다

시드별 `rho / 효과크기`:

  `st1_pa3_vmf10` 은 5/5 음수, `vmf_k20` 은 5/5 양수다. 즉 **재현되는 방향 자체가 없다.**
- 반면 **`gaussfix_b0` 계열은 세 카테고리 전부 rho +1.00, 전 시드**다. 데이터의 성질이 아니라
  **latent 이 학습한 구조의 문제**라는 뜻이다.

### 6-2. 가설 (a) 시작 상태 `x0` — 기여하지만 주원인은 아니다

`--x0_source {A,B}` 를 추가해 공통 시작 상태를 느린 클립(A) / 빠른 클립(B) 것으로 각각 썼다.

| `vmf_k10` | +1.00 → +0.84 | **−0.98 → +0.72** | −0.03 → +0.00 |
| `st1_pa3_vmf10_s1` | +1.00 → +0.99 | **−1.00 → −1.00** | **−0.98 → −0.97** |
| `gaussfix_b0_s0` | +1.00 → +1.00 | +1.00 → +1.00 | +1.00 → +1.00 |

`walk` 는 `x0` 에 무관하게 양수다. `run`/`trot` 은 `pa3_vmf10`·`vmf_k10` 에서 `x0` 를 바꾸면
부호가 사라지지만, `st1_pa3_vmf10` 은 양쪽 모두 −1.00 이다.
→ **`x0` 상호작용은 기여 요인이지만 단독 원인은 아니다.**

### 6-3. 가설 (b) latent 이 gait 를 먼저 인코딩한다 — **확정. 주원인이다**

`walk` **121 클립으로만** `z -> vx` 선형 프로브를 적합하고 `run`/`trot` 에 적용했다.
walk 는 121 클립 / 18 차원이라 이 적합은 미결정계가 아니다 — 지표로 신뢰할 수 있다

−0.52 ~ +0.46). **판정 근거는 위의 전이 상관이며 코사인은 참고로만 읽을 것.**
전체 수치는 `axis_alignment.txt`.

### 6-4. 교차 카테고리 — 방향은 맞지만 효과가 미미하다

| 체크포인트 | 느린 walk → 빠른 run | 느린 walk → 빠른 trot | 느린 trot → 빠른 run |
|---|---|---|---|
| `pa3_vmf10` | +0.87 / 6.2% | +1.00 / 17.6% | **−0.98** / 26.5% |
| `st1_pa3_vmf10_s1` | +0.97 / 4.4% | +0.76 / 2.3% | **−0.80** / 10.0% |
| `vmf_k10` | +0.86 / 3.1% | +0.55 / 4.8% | **−0.95** / 6.3% |
| `gaussfix_b0_s0` | +1.00 / 35.2% | +1.00 / 30.3% | **+1.00** / 45.4% |

vMF latent 은 "walk 가 run 보다 느리다"는 것은 **알지만 약하게(3~6%)** 알고,
**고속 영역 안(trot↔run)에서는 순서를 반대로 매긴다.**

### 6-5. 부수 관측 — 빠른 클립일수록 대표방향이 흐려진다

vMF 에서 클립 대표방향의 resultant `||mean(mu)||` 와 클립 평균 vx 의 상관:

```
pa3_vmf10          -0.460
st1_pa3_vmf10_s1   -0.541
gaussfix_b0_s0     +0.172   (Gaussian, 노름은 자유)
```

빠른 클립일수록 스텝별 `mu` 가 구 위에 넓게 흩어져 평균이 상쇄된다. 카테고리별 resultant 중앙값:

| 설정 | walk | run | trot |
|---|---|---|---|
| `vmf_k10` | 0.313 | 0.155 | 0.160 |
| `pa3_vmf10` | 0.287 | 0.208 | 0.222 |
| `st1_pa3_vmf10` | 0.293 | 0.166 | 0.190 |

대표방향이 더 흐린 만큼 그 위에서 잰 보간도 불안정하다.
6-3 만큼 결정적이지는 않지만 같은 방향의 증거다.

**참고**: `gaussfix_b0` 에서 `||z_clip||` 과 vx 의 상관은 +0.172 로 낮다.
즉 속도가 **크기**로 인코딩된 것은 아니다 — "vMF 는 노름이 1 이라 속도를 못 담는다"는
설명은 성립하지 않는다. 문제는 크기가 아니라 **방향축의 카테고리 의존성**이다.

### 7-1. 산출물로 쓸 것

**`st1_pa3_vmf10` (stride 1, predict_ahead 3, κ 고정 10) — 단, 저속 전용.**

| | 스텝 | 생성률 | 시드 | walk 효과 최악값 | G1 |
|---|---|---|---|---|---|
| `pa3_vmf10` (stride 2) | 100 ms | 10 Hz | 5/5 | 18.1% | 1.77 |
| **`st1_pa3_vmf10`** (stride 1) | **50 ms** | **20 Hz** | 5/5 | 10.5% | 1.93 |

`pa3_vmf10` 의 효과크기가 더 크지만 **생성률이 10 Hz** 다. 디코더가 `x[t] -> x[t+k]` 로
**k 프레임을 건너뛰므로** Phase 2 는 그 주기를 그대로 받거나 중간을 보간해야 한다.
20 Hz 는 쓸 수 있고 10 Hz 는 어렵다.

`st1_pa3_vmf10` 의 최악 시드 효과가 10.5% 로 기준 10% 에 근접한다는 점을 함께 적어 둔다.

### 7-2. Phase 2 로 넘어가기 전에 풀어야 할 것

부호 반전(§6)이 미해결이라 **synthesis 정책이 전 명령 범위에서 "속도를 올리는 latent 방향"을
일관되게 학습할 수 없다.** 저속(walk, 0.01~1.23 m/s)에 한정하면 지금 latent 으로도 가능하다.

다음 후보 (본 세션에서는 미시도):

| 후보 | 근거 |
|---|---|
| **속도 조건부 인코더** | `z` 에 속도를 담지 말고 `(z, v_cmd)` 를 디코더에 함께 준다. 카테고리별 축 문제를 우회한다 |
| **속도축 정렬 손실** | 카테고리별 `z -> vx` 축이 같아지도록 보조 손실을 건다. §6-3 이 그대로 목적함수가 된다 |
| **데이터 불균형** | val 기준 walk 121 / run 16 / trot 16. 고속 클립이 8배 적다. train 도 유사하면 고속 영역 축이 부실할 수밖에 없다 — **먼저 확인할 것** |
| `gaussfix_b0` 정규화 | 전역 축은 유일하게 이 계열만 갖는다. §5 표대로 6 설정 전부 트레이드오프에 걸렸으나, weight decay·dropout 등 다른 축은 미시도 |

**퇴로는 유효하다** — 상위 보고서 §5 의 안 B(latent 을 생성이 아니라 스타일 채점에만 사용)는
디코더를 쓰지 않으므로 §6 의 영향을 받지 않는다. 인코더는 `G2a` R² 0.82~0.85 로 정상이다.

## 8. 검증

- **vMF 샘플러 단독 검증** — 100k 표본, κ ∈ {1, 5, 10, 20, 50, 100, 500}:
  `||z||` 오차 1e-6 이내, `E[z·mu]` 가 `ive(9,κ)/ive(8,κ)` 와 최대 0.0011 차.
  `mu` 로의 gradient 전파 확인. KL 은 κ→0 에서 2.8e-8 로 수렴.
- **Gaussian 회귀 확인** — `regress_gauss` 가 기존 `../final_s2_strat/` 과 완전 일치
  (G1 1.580, G0 1.05, `r_enc` 0.027078). 기존 경로 무손상.
- **eval 정정 2건**
  - `z=0` 은 vMF 에서 **구 위에 없는 점**이다. 그 비율은 latent 활용의 증거가 아니므로
    `[무효-구밖]` 으로 표기하고 **단위 난수 z** 를 함께 잰다.
  - 대표방향 평균 후 **재정규화**, 보간은 **slerp**. 선형보간은 α=0.5 에서 `||z||` 가
    `cos(theta/2)` 로 줄어 효과크기가 "크기 축소" 아티팩트와 섞인다.
- **알려진 한계** — 클립 대표방향의 resultant 가 walk 0.29 로 낮다. 스텝별 `mu` 가 보행 주기에서
  상당히 상쇄되므로, G2b 곡선은 개별 스텝이 점유하지 않는 방향 위에서 잰 값이다.
  LOO R² 0.82(121 클립)가 그 방향에 실제 속도 정보가 있음을 뒷받침하므로 결과는 유지하되
  구조적 한계로 남는다.
- **lint** — `ruff format` 통과. 남은 SIM115/SIM113 5건은 전부 기존 줄(`json.load(open(...))` 등)이며
  이번 변경으로 추가된 것은 없다.

| 합계 | 91,563 | | 555 | 35 | |

팀리드 측정치와 일치한다. 다만 **`trot` 의 train 세션은 6개가 아니라 4개**다
(전체 6개 중 2개가 val 로 갔다). 희소성은 보고서보다 한 단계 더 심하다.

**미러 클립 처리** — 미러(`__M_`)는 좌우 복제라 다양성 기여가 0 이지만 실제 학습 표본이므로
**균형 계산에 포함**했다. 미러가 카테고리별로 대략 절반씩(walk 22,466 / run 3,377 / trot 1,461)
고르게 있어 제외해도 비중은 거의 같다.

## 11-2. 구현

```
--balance {none, inverse, sqrt}      none = 프레임 비례(현행)
                                     inverse = 그룹별 표본 수의 역수 -> 균등
                                     sqrt    = 역수의 제곱근 -> 완화된 균형
--balance_by {category, session}     균형의 단위
--balance_groups {main, prefix}      category 일 때의 묶음
```

```
n_g      = 그룹 g 의 상태전이 쌍 개수
w_sample = (1 / n_g)          scheme = inverse
         = (1 / n_g) ** 0.5   scheme = sqrt
가중치 합은 표본 수로 정규화 -> epoch 당 기대 표본 수는 none 과 동일
```

- **상태전이 배치와 autoregressive 윈도우 양쪽에 같은 가중치**를 건다.
  윈도우는 쌍에서 구한 그룹별 배율을 재사용한다.
- `--balance_groups main` 은 `walk / run / trot / other` 4군이다.
  접두사 12종을 그대로 균등화하면 `lie_trot`(118 프레임, 1 세션)이 **64.7배**로 뻥튀기되어
  소수 클립 과적합이 가설 검증을 오염시킨다. 그래서 기본값을 `main` 으로 뒀다.
- **실제 추출 비중 확인** — `inverse` 목표 25.0% 대비:

| | 쌍 (설계) | 윈도우 stride 1 | 윈도우 stride 2 |
|---|---|---|---|
| walk | 25.0% | 25.5% | 26.6% |
| other | 25.0% | 26.0% | 27.3% |
| run | 25.0% | 24.3% | 23.4% |
| trot | 25.0% | 24.2% | 22.8% |

최대 이탈 2.3 %p 로 "반쪽 균형"은 발생하지 않았다.
다만 stride 2 에서는 **trot 26 클립 중 16개가 AR 윈도우를 하나도 못 만든다**
(클립이 `ar_len × k = 24` 스텝보다 짧다). 남은 10개가 그만큼 더 뽑힌다.

**기존 경로 무손상 확인** — `--balance none` 은 기존과 동일한 `randperm`/`randint` 경로를 탄다.
`st1_pa3_vmf10_s0` 재현 결과 in-sample 0.014023 / held-out 0.027007 / 비율 1.926× 로
기존 로그와 **완전히 일치**한다.

판정 기준선 `regress_gauss` 가 전이 상관 +0.18 / +0.09 인데 효과크기가 0.1% 다 —
**아무것도 하지 않는 latent 이 0 근처를 낸다.** 그래서 전이 상관은 단독으로 읽으면 안 된다:

```

전이 ~= 0     AND  walk 효과 하락                            ->  축이 지워진 것 (FAIL)
```

읽으면 안 된다 — 같은 arm 의 walk 효과가 11.7% [6.2~15.6] 로 흔들리고 G1 이 2.05 로 이탈해
**0/3** 이다. 생성기가 망가진 채 나온 0 이지 정렬된 0 이 아니다.

**이 arm 이 가장 유용한 증거다.** 균형이 깨끗하게 걸렸고(효과·G1·val_rec 어느 것도 손해 없음)
그럼에도 **축은 전혀 움직이지 않았다.** 악화만 있는 결과였다면 "균형을 너무 세게 걸었다"로
치부할 수 있지만, 비용 없이 걸린 arm 에서도 축이 그대로면 그 해석은 성립하지 않는다.

## 11-5. 왜 가설이 틀렸나 — 같은 데이터로 축을 만든 설정이 이미 있다

결정적 반증은 새 실험이 아니라 **기존 대조군**에 있다.

```
gaussfix_b0 는 balance=none 으로 학습한다. 즉 walk 71.9% 의 **똑같이 불균형한 데이터**를 본다.
그런데 walk 프로브 -> run 전이 +0.90, -> trot +0.94 로 전역 속도축을 갖는다.
```

불균형이 원인이라면 같은 불균형 데이터를 본 이 설정도 축이 깨져야 한다. 깨지지 않는다.
**따라서 부호 반전의 원인은 데이터 분포가 아니라 latent 매개화(vMF 고정 κ)다.**

균형 샘플링이 `bal-inv_gfb0` 에서 전이 상관을 +0.94 → +0.98 로 조금 올린 것은
이미 옳은 축이 있을 때의 미세 개선이지, 없는 축을 만들어 내지는 못한다.
그리고 그 대가로 G1 이 2.01 → **2.24** 로 더 나빠져 **§5 의 정면 트레이드오프는 깨지지 않았다.**

**세션 균형이 왜 무력한지**도 구조로 설명된다. train 35 세션 중 **27개가 walk 를 담고
trot 은 4개뿐**이다. 세션을 균등화해도 walk 비중은 71.9% 에서 크게 안 내려간다 —
이건 카테고리 균형 처방이 아니다. `bal-sess` 가 기준선과 비슷하게 나온 것은 실패가 아니라
**예상된 무효과**다. "trot 축이 소수 세션에 의존한다"는 질문의 올바른 검사는
샘플링 가중치가 아니라 **trot 세션 leave-one-out** 이다 — 가중치는 없는 세션을 만들지 못한다.

목적함수로 직접 제약하는 것이 맞다. §6-3 의 전이 상관이 그대로 손실 형태가 된다.

# 12. 축 정렬 손실 — **부분 성공 / 최종 FAIL**

§11 에서 데이터 쪽으로는 못 고친다는 것이 확인됐으므로, 전역 속도축을 **목적함수로 직접 강제**했다.
결과: **부호는 고쳤다. 크기는 못 고쳤다.** run/trot 의 rho 를 −1.00 → +1.00 으로 뒤집는 데는
성공했지만, 그 대가로 walk 효과크기가 단조 감소하고 run/trot 효과크기는 끝내 10% 를 넘지 못했다.

## 12-1. 구현

```
보조 헤드   v_hat   = w_head . z + b        # walk/run/trot 이 **하나의 (w, b) 를 공유**
보조 손실   L_speed = mean( (v_hat - vx_true)^2 )
전체 손실   L       = L_recon + beta*L_kl + lambda_speed * L_speed
```

| 기호 | 의미 | 비고 |
|---|---|---|
| `z` | 인코더 사후 평균 `mu` (vMF 면 단위벡터) | **detach 하지 않는다** — gradient 가 인코더까지 흐른다 |
| `w_head`, `b` | 공유 선형 속도 헤드 | `nn.Linear(latent_dim, 1)` |
| `vx_true` | 표적 전진속도 (정규화 공간) | `--speed_target step` = 해당 전이의 순간 vx, `clip` = 그 클립의 평균 vx |
| `lambda_speed` | 보조 손실 가중치 | 0 / 0.1 / 0.3 / 1.0 / 3.0 / 10.0 |

- **상태전이 배치와 autoregressive 롤아웃 양쪽**에 손실을 건다 (§11 의 "반쪽" 교훈).
- `--balance_speed_only` — `--balance` 가중치를 **샘플링이 아니라 보조 손실에만** 적용한다.
  walk 가 71.9% 라 그냥 두면 공유 `w` 가 walk 에 맞춰진다.
- `speed_head` 는 `__init__` 의 **맨 마지막**에 만든다. 앞에 두면 나머지 파라미터의 초기화 RNG 가
  밀려 `--lambda_speed 0` 이 기존과 달라진다. 구 체크포인트에는 이 키가 없으므로
  eval·진단 스크립트는 `strict=False` 로 읽되 **`speed_head.*` 이외의 키 불일치는 에러로 막는다.**

**기존 경로 무손상 확인** — `--lambda_speed 0` 재현이 in-sample 0.014023 / held-out 0.027007 /
비율 1.926× 로 `st1_pa3_vmf10_s0` 기존 로그와 **완전히 일치**한다.
기존 체크포인트 로드·평가도 정상(walk R² 0.890, 효과 10.5%).

**제약은 충족 가능하다** — 공유 `w` 하나로 `L_speed` 가 0.0123(λ=0.1) ~ 0.00043(λ=10)까지 내려간다.
정규화 공간에서 vx 분산이 1.0 이므로 λ=1.0 의 0.0022 는 학습 `R^2 ≈ 0.998` 이다.
즉 "단일 축으로 전 카테고리를 맞추는 것" 자체는 인코더가 해낸다.

## 12-2. ★ 판정 지표가 두 개 무효화됐다 — 먼저 읽을 것

`L_speed` 는 **"z 에서 선형으로 vx 를 복원한다"** 를 목적함수로 삼는다.
그런데 `G2a`(선형 프로브 LOO R²)와 **전이 상관**(walk 로 적합한 선형 프로브를 run/trot 에 적용)은
**같은 함수 형태**다. 따라서 이 둘은 `sp*` arm 에서 **보조 손실이 수렴했는지를 되읽는 것**이지
독립 증거가 아니다.

`G2a` 가 λ 에 따라 단조 상승하는 것이 그 증거다:

```
기준선 0.82~0.85  ->  λ 0.1: 0.84~0.88  ->  λ 1.0: 0.97~0.99  ->  λ 10: 0.99~1.00
```

전이 상관은 **더 나쁘다 — 디코더 측정과 부호가 어긋나는 사례가 있다.**

| arm | 전이 →run / →trot | G2b run rho/eff | G2b trot rho/eff |
|---|---|---|---|
| `sp1.0_pa3` | **−0.88 / −0.90** | **+1.00** / 7.2% | **+1.00** / 13.3% |

전이 상관은 "축이 뒤집혔다"고 하는데 디코더는 세 카테고리 전부 단조 증가다.
전이 상관은 walk 클립 121개로 프로브를 **다시 적합**하므로 학습된 `w_head` 와 다른 방향을
집을 수 있고, `sp*` arm 에서는 그것이 실제로 일어난다.

> **따라서 팀리드가 세운 "전이 상관 ≥ +0.5" 목표는 `L_speed` arm 에 대해 무효다.**
> 그 기준으로 줄을 세우면 walk 효과 4.5% 인 `sp10.0_pa3`(전이 +0.96/+1.00)가

> **판정은 `G2b`(디코더 민감도) 단독으로 한다.**

## 12-4. 읽기

**(1) 부호는 고쳐진다.** λ ≥ 1.0 에서 run·trot rho 가 **+1.00** 으로 뒤집힌다. 전 시드, 두 계열 모두.
§6 부터 지금까지 어떤 처방으로도 안 됐던 것이 처음 됐다. 축 정렬 손실은 **의도한 대로 작동한다.**

**(2) 크기는 안 고쳐진다.** run/trot 효과크기가 10% 를 넘는 조합이 없다
(넘는 경우 walk 이 무너진다 — `spclip_pa3` trot 20.0% / walk 9.1%).
**walk 효과크기는 λ 에 대해 단조 감소한다**: 23.3 → 21.6 → 14.6 → 13.2 → 9.0 → 7.7 → 4.5%.

**(3) 프론티어 지점** — `spbal_pa3` (λ=1.0, step, 균형은 보조 손실에만).
**전 카테고리 rho 양수 + walk 3/3 PASS 를 동시에 만족한 유일한 arm** 이다.
그러나 run 4.2% / trot 9.0% 로 둘 다 10% 미달이라 **최종 FAIL** 이다.
양옆이 이 지점을 프론티어로 확정한다 — `sp0.1_pa3` 는 walk(21.6%)를 지키고 부호를 잃고,
`sp10.0_pa3` 는 부호를 지키고 walk(4.5%)를 잃는다. 튜닝을 덜 한 게 아니라 **교환 곡선**이다.

**(4) 표적을 바꿔도 같다.** `--speed_target clip` 은 게이트가 재는 양(클립 평균 vx)을 그대로
표적으로 삼는 변형인데, `spclipbal_pa3` 가 walk 10.3% / run 3.8% / trot 9.7% 로 같은 벽에 막힌다.
**step / clip / 균형 세 가지 독립 형식이 같은 방식으로 실패한다.**

**(5) `val_rec` 이 다시 판정을 바꿨다.** G1 은 λ 전 구간에서 1.71~1.99 로 거의 안 움직이는데
절대 `val_rec` 은 **단조 상승**한다 — stride 2: 0.06673 → 0.09349(**+40%**),
stride 1: 0.02701 → 0.04384(**+62%**). 비율이 생성기 악화를 가린다. §11 에 이어 두 번째다.

## 12-5. 판정

| 항목 | 목표 | 결과 | 판정 |
|---|---|---|---|
| run/trot rho 부호 반전 | 양수 | λ ≥ 1.0 에서 **+1.00** | **PASS** |
| run G2b 효과크기 | ≥ 10% | 2.6 ~ 10.8% (walk 유지 시 ≤ 4.2%) | **FAIL** |
| trot G2b 효과크기 | ≥ 10% | 3.9 ~ 20.0% (walk 유지 시 ≤ 10.8%) | **FAIL** |
| walk 효과 유지 | ≥ 10% | λ ≥ 1.0 에서 붕괴 (3.4 ~ 9.1%) | **FAIL** |
| G1 ≤ 2.0 | 유지 | 1.71 ~ 1.99 유지 (단 `val_rec` +40~62%) | PASS (단서 있음) |
| 전이 상관 ≥ +0.5 | — | **무효** (§12-2, 순환) | 판정 제외 |

**최종 FAIL.** 축 정렬 손실은 방향을 고치지만 **전 속도역을 조종 가능한 latent 을 만들지 못한다.**

## 12-6. 다음에 대한 판단

`step` / `clip` / `balanced` 세 형식이 같은 벽에 막혔고, 인코더는 공유 `w` 를 `R^2 ≈ 0.998` 로
맞추는데도 디코더 민감도가 안 따라온다. 이는 **18-D vMF 구 위의 단일 선형 축으로는 두 속도역을
동시에 섬길 수 없다**는 쪽을 시사한다 — §6-3 의 축 반정렬이 학습 아티팩트가 아니라 기하 제약일
가능성이다. 같은 계열의 네 번째 변형을 더 돌릴 근거는 없다고 본다.

남은 선택지는 성격이 다른 것들이고, **어느 쪽으로 갈지는 팀리드 판단이다**:

| 선택지 | 근거 / 비용 |
|---|---|
| latent 차원 확대 | 축이 겹치지 않을 공간을 준다. 단 §5 에서 차원을 **줄이면** G1 이 좋아지고 효과가 죽는 관계가 이미 관측됐다 — 늘리면 G1 이 나빠질 공산 |
| 속도 조건화 (§7-2) | `z` 에 속도를 담지 않고 `(z, v_cmd)` 를 디코더에 준다. 축 문제를 **우회**한다. 지금까지 결과와 충돌하지 않는 유일한 구조 변경 |
| 저속 전용으로 확정 | `st1_pa3_vmf10` 을 walk 영역(0.01~1.23 m/s) 한정으로 Phase 2 진행 |
| 안 B (스타일 채점) | 디코더를 쓰지 않으므로 §6 의 영향을 받지 않는다. 인코더는 정상 |

**권고는 바뀌지 않는다** — `st1_pa3_vmf10` (20 Hz, 저속 전용, 5/5).
어떤 `sp*` arm 도 walk 게이트에서 이것을 넘지 못했다.
