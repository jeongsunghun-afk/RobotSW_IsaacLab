# go2_pedipulation

Go2 의 **한 다리를 조작기로 쓰는(pedipulation)** task. 명령받은 다리의 발을 명령받은 위치로
옮기고 유지하며, 나머지 세 다리로 균형을 잡는다. S2 에서는 정지 목표 대신 **연속 궤적(원)**
을 따라간다.

| gym task id | 등록 위치 |
|---|---|
| `Go2-Pedipulation-v0` | `direct/go2_pedipulation/__init__.py` |

- 로봇: Unitree Go2 (12-DOF 4족), 평지
- 알고리즘: PPO (`rsl_rl`), AMP 미사용
- 게이트 평가: `scripts/reinforcement_learning/rsl_rl/play_pedipulation_gates.py`
  (`--mode push|drift|hold|circle|contact|video|showcase|contactvid`)
- 계획·구현 로그: `.omc/research/pedipulation/PLAN.md`, `.omc/research/pedipulation/IMPL_LOG.md`

## 표기 읽는 법 — S1/S2, G1/G2, run 이름

이 문서와 로그 전체가 쓰는 약어다. 원본 정의는 `PLAN.md` §5.

### S1~S5 는 난이도 단계가 아니라 **명령 분포**다

핵심 설계: **env 는 하나뿐이고, 단계는 "어떤 명령을 주느냐"로만 구분된다.** 단계마다 새 환경을
만들지 않으므로 obs/action 차원이 고정되고, 앞 단계에서 fine-tune 으로 이어갈 수 있다.

| 단계 | 한 줄 정의 | 명령이 무엇인가 |
|---|---|---|
| **S0** | 이식·baseline | — |
| **S1** | 정지 목표에 발을 갖다 대고 **유지** | 고정된 점 하나 |
| **S2** | **움직이는** 목표 따라가기 | 시간에 따라 움직이는 점 (원 궤적) |
| **S3** | 조작하는 **발을 바꾸기** | 도중에 leg-role 이 바뀐다 |
| **S4** | 접촉 **품질·안전** | S1 과 같되 실제로 물체에 닿는다 |
| **S5** | 실제 task | 악수 / 물건 터치 / 공 굴리기 (D5) |

### G 번호는 그 단계의 합격 조건 체크리스트다

`S1-G5` = "S1 단계의 5번째 합격 조건". 자주 인용되는 것만:

| 게이트 | 무엇을 재나 | 기준 |
|---|---|---|
| S1-G1 | 발이 목표에 얼마나 가까운가 | ≤ 0.05 m |
| S1-G2 | **작업공간 전체**에서 되는가 (0.1 m 격자 144 셀) | 셀의 ≥90% 가 ≤ 0.08 m |
| S1-G3 | 유지하는 동안 흔들리지 않는가 | 오차 std ≤ 0.02 m |
| S1-G5 | **밀어도 안 넘어지는가** (50~300 N) | 3족 `<150 N` 성공률 ≥ 70% |
| S1-G7 | **몸통이 얼마나 움직이는가** | 중앙값 ≤ 0.05 m |
| S2-G1 | 원 궤적 추종 오차 | 각속도별 0.035 / 0.045 / 0.06 m |
| **S4-G4 ①** | 접촉할 때 **그 발에 체중이 실리는가** | **위반 0건 — hard constraint** |

**S4-G4 ① 만 성격이 다르다.** 나머지는 성능 기준이라 조금 못 미쳐도 다른 것과 교환할 수 있지만,
이건 안전이다. Go2 자중 **147.3 N > ISO/TS 15066 사람 손 접촉 한계 140 N** 이므로 조작 발로
체중이 넘어가면 **접촉력이 작아도 위험**하다. 그래서 힘 크기가 아니라 "체중이 넘어갔는가"를 본다.

## 이 task 에서 확정된 것

**① 유지 중 떨림의 원인은 관측 노이즈다 — 물리 DR 은 사실상 무기여.**
3-way A/B (`--mode hold`, 288 env, hold 5 s 중앙값):

| 조건 | 관절 목표 흔들림 [deg/step] | jvel RMS | 발 위치 std |
|---|---|---|---|
| 전체 DR ON | 2.57 | 0.197 | 4.25 mm |
| **관측 노이즈만 끔** (물리 DR 유지) | **0.00004** | 0.012 | 0.03 mm |
| DR 전부 끔 | 0.00003 | 0.009 | 0.01 mm |

관측 노이즈만 꺼도 DR 을 전부 끈 것과 같은 자릿수로 떨어진다.

**② 원 반경 0.20 m 는 Go2 다리로 기구학적으로 불가능하다.**
관절 한계 격자 실측(thigh×calf 120×120, hip=0) 결과 **최대 도달 원 0.140 m**.
→ r = 0.10 m 채택, sweep 축을 접선속도에서 **각속도**로 전환해 PLAN 임계값을 그대로 재사용.

**③ "push 학습이 강건성을 샀다"는 1차 귀인은 틀렸다.**
대조군 `s2_nopush` 로 갈라 보면 이득의 70%가 **circle 학습**에서 나온다:

| 150 N 3족 성공률 | smooth4x | s2_nopush | s2_circle |
|---|---|---|---|
| | 53.0% | **72.1%** | 80.4% |

정책 채택 결정은 바뀌지 않고 인과 설명만 바뀌었다.

**④ `_post_physics_step` 은 `DirectRLEnv` 훅이 아니다 — 이 저장소 8개 env 가 정의했지만
실제 호출은 1곳(`skeleton_wtw_env.py:276`)뿐이었다.** 이 env 에서는 궤적 진행·에피소드 중
명령 재샘플·DR base push 세 기능이 S1 학습 내내 무효였다. `_get_dones` 첫머리에서 명시 호출로
수정. **S1 게이트 측정치는 영향 없다** — 평가가 `resample_time=1e6` 고정 + push 직접 주입이라
버그 유무와 무관하게 같은 조건이었다. 나머지 7개 env 는 학습 동작 변화 우려로 미수정.
