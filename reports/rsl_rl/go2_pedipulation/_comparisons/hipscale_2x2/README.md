## 답 ① hipON 4배의 실패는 hip 축소가 원인이다

같은 4배 규제인데 hip 축소를 끄면 정상 학습된다.

| | 커리큘럼 승급 | 최종 `cmd_box_x` | 최종 `Policy/mean_std` |
|---|---:|---:|---:|
| hipON 4배 | **0 회** / 9891 평가 | 0.060 = 초기값 | **2.826** (단조 발산) |
| hipOFF 4배 | 7726 회 | **0.200** = 최대 | 1.317 |

기전: hip 축소는 좌우 균형의 주 액추에이터 권한을 절반으로 줄인다. 4배 규제로는 그 상태에서
안정적인 해를 찾지 못해 정책 분산이 발산했고, 10배의 강한 action 페널티는 고분산 액션을 직접
억제해 발산에 반대로 작용한다.

⚠ **칸당 n=1 이다.** 2×2 의 방향이 일관되므로 요인 효과로 읽지만, "4배+hip ON 은 반드시
실패한다"가 아니라 **"hip 축소가 4배에서 학습을 무너뜨렸다"** 까지가 말할 수 있는 범위다.
단정하려면 hipON 4배를 다른 시드로 재실행해야 한다.

## 답 ② hip 축소의 대가는 사실상 없다

10배끼리(유일한 순수 단일 변수 A/B):

| | hipOFF 10배 | hipON 10배 | 차이 |
|---|---:|---:|---|
| hold | 8.65 mm | 9.32 mm | OFF 0.67 mm 우세 |
| 떨림 | 0.878 | **0.823** | **ON 우세** |
| push 150 N | 79.5% | 78.1% | 통계적 동일 |
| push 200 N | 51.1% | 45.2% | 통계적 동일 |
| 원 RMSE | 12.32 mm | 13.44 mm | OFF 우세 |
| 접촉 하중 | 17.6% | **14.9%** | **ON 우세** |
| 측정 타당성 (4족/3족) | 0.893 / 0.998 | **0.994 / 0.994** | **ON 우세** |

**push 차이는 유의하지 않다.** Wilson 95% 구간이 크게 겹친다 (셀당 n=219):

| | 150 N | 200 N |
|---|---|---|
| hipOFF 4배 | 82.2% [76.6, 86.7] | 47.9% [41.4, 54.5] |
| hipOFF 10배 | 79.5% [73.6, 84.3] | 51.1% [44.6, 57.7] |
| hipON 10배 | 78.1% [72.1, 83.1] | 45.2% [38.8, 51.8] |

"hip 은 좌우 균형의 주 액추에이터이므로 push 가 떨어질 것"이라는 사전 예측은 **틀렸다.**
학습이 성립하기만 하면 정책이 나머지 자유도로 보상한다.

## 답 ③ `smooth4x` 는 버그 덕을 본 것이 아니라 손해를 봤다

`hipoff_4x` 가 `smooth4x` 의 정정판이다 (같은 보상, 명령 재샘플링이 실제로 동작).

| | `smooth4x` (버그) | `hipoff_4x` (정정) |
|---|---:|---:|
| hold | 10.18 mm | **9.23 mm** |
| 떨림 | 1.29 | **1.173** |
| step 재수렴 p95 | 0.68 s | **0.34 s** |
| 원 RMSE | 17.24 mm | **13.19 mm** |
| push 150 N | 53.0% | **82.2%** |
| 표류 | 6.28 cm | 6.98 cm |

명령 분포가 더 어려워졌는데도 표류 하나 빼고 전부 개선됐다. **"명령이 안 바뀌어서 hold 가
좋아 보였다"는 가설은 기각된다** — 오히려 명령 변화를 겪지 못해 step 응답과 push 가 나빴다.

⚠ 다만 `smooth4x` 는 13599 iteration, 정정판은 20000 이다. 개선폭 중 얼마가 iteration
덕인지는 이 쌍으로 가를 수 없다.

## 채택 — `hipON 10배` (2026-08-05 반영 완료)

세 칸이 사실상 동률이므로 **sim2real 요구가 tie-breaker** 다. `hip_scale_reduction=True` 는
실기 배포를 위해 도입한 것이고, 위 표대로 그 대가가 측정 한계 안에 있다. 떨림·접촉 하중·측정
타당성에서는 오히려 앞선다.

직전 채택 정책 `jtr40_jvf` 대비:

| | `jtr40_jvf` | `hipON 10배` |
|---|---:|---:|
| hold | 15.60 mm | **9.32** |
| 떨림 | 1.42 | **0.823** |
| step p95 | 4.37 s | **0.38** |
| 원 RMSE | 19.72 mm | **13.44** |
| push 150 N | 76.5% | 78.1% |
| S4 위반 / 하중 | 0.05% / 24.5% | **0.00% / 14.9%** |
| 표류 | **5.52 cm** | 7.88 |

표류 하나만 열세다. **2026-08-05 에 교체를 반영했다** — 채택본은
[`../../2026-08-03_15-53-29_hipscale_scratch_s10x/`](../../2026-08-03_15-53-29_hipscale_scratch_s10x/)
의 `model_19999.pt` 다. pedipulation 은 배포·export 경로가 아직 없으므로 채택은 **문서상
지정**이고, 코드에 박힌 기본 체크포인트는 없다.

⚠ **배포 전 확인 필요**: `scripts/real2sim/r2s_go2/policy_runtime.py` 의
`action_to_target_art()` 에는 hip 축소가 없다. 이 정책을 실기로 내보내면 hip 명령이 2배가
된다. 옆의 `recovery_runtime.py` 에는 있어서 둘 다 맞다고 착각하기 쉽다.

## 남은 열세 — 몸통 표류

네 칸 모두 표류 게이트(≤5 cm)를 통과하지 못한다 (6.98 ~ 7.88 cm). 다만 **후반 표류는
0.45 cm** 수준으로, 누적 이동이 아니라 초기 재배치다. 표류를 직접 줄이는 `w_base_drift` 는
S4 하중 전이 위반을 0.05% → 19.19% 로 만든 항이라 되살리지 않는다. 표류를 더 줄이려면
S4 를 깨지 않는 다른 항이 필요하다.
