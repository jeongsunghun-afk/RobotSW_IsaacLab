|---|---|---|

네 칸 모두: from scratch, seed 42, 2048 env, 20000 iteration, `w_base_drift=0`,

## 왜 아래쪽 두 칸을 새로 도는가

기존 계보의 기준선 `smooth4x` 는 **비교 기준으로 쓸 수 없다.** `_post_physics_step` 이
`DirectRLEnv` 의 훅이 아닌데 훅인 것처럼 정의만 되어 있어 **호출되지 않았고**, 그 결과
`_cmd_timer` 가 줄지 않아 **에피소드 중 명령이 한 번도 바뀌지 않은 채** 학습됐다.
`params/env.yaml` 은 `resample_time 3.0/5.0` 을 기록하지만 그 코드는 실행되지 않았다 —
설정 파일만 보면 알 수 없는 종류의 실패다.

버그는 `890a3174dc4` 에서 고쳐졌다 (`go2_pedipulation_env.py:761`, `_get_dones` 에서 호출).
위 네 run 은 전부 고쳐진 env 로 돈다.

따라서 `smooth4x` 와 새 run 의 격차에는 **두 요인이 섞여 있다** — hip 축소와, 실제로
동작하게 된 명령 재샘플링. 아래쪽 두 칸이 그 교란을 제거한다:

- **`hipoff_4x`** = "`smooth4x` 를 제대로 다시 한 것". 명령 분포 요인만 분리한다.
- **`hipoff_10x`** = 유일하게 학습에 성공한 arm(`hipscale_scratch_s10x`)의 **순수 단일 변수
  대조군**. 이 둘의 차이만이 hip 축소가 매기는 값이다.

## 이 2×2 가 답하는 질문

1. **hip ON · 4배의 실패는 hip 축소 탓인가, 규제 배율 탓인가, 우연인가?**
   `hipoff_4x` 가 성공하면 hip 축소가 4배에서 학습을 무너뜨렸다는 뜻이다. 같이 실패하면
   원인은 hip 축소가 아니라 규제 배율(또는 고쳐진 명령 분포)이다.
2. **hip 축소가 성능에 매기는 값은 얼마인가?**
   `hipoff_10x` vs `hipscale_scratch_s10x` 가 유일한 순수 A/B 다. push 강건성이 주 관측
   대상 — hip 은 좌우 균형의 주 액추에이터다.
3. **`smooth4x` 의 hold 10.18 mm 중 얼마가 "명령이 안 바뀌는 쉬운 조건" 덕이었나?**
   `hipoff_4x` 가 그 값을 대체한다.

## 한계 — 칸당 n=1

std 발산은 확률적 실패 모드다. 시드를 같게(42) 해도 보상 가중치가 다르면 첫 업데이트부터
궤적이 갈라지므로 시드 통제는 성립하지 않는다. **네 칸이 다 나와도 "A 는 구조적으로 불가능"
같은 단정은 하지 않는다.** 2×2 의 두 대각이 일관된 방향을 가리킬 때만 요인 효과로 읽고,
어긋나면 재시드가 필요하다고 기록한다.
