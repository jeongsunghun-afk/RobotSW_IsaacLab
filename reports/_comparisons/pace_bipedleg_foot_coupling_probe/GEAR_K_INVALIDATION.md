# ⚠ gear_k 미적용 — 2026-08-13 이전 biped_leg 실기 캡처·PACE 적합 전량 무효

**결론: 브리지가 채널각을 관절각으로 취급한다.** `calib_bipedleg.hpp` 자체가 2026-08-10 인계
시점에 이 갭을 적어 뒀는데(§구조적 갭 1번) 구현되지 않은 채로 남았다. 그 결과 **calf·foot 두 축의
모든 각도·명령이 각각 1.5배 / 1.2배 어긋난 상태**로 데이터를 모았고, 그 위에서 PACE 적합을 돌렸다.

## 1. 근거

`RL_INTERFACE.md` §3~§4 (config 원본 `config/biped_emb.yaml`):

```
보고각 = 실제 관절각 × (실제감속비 / 7)     →  gear_k = 실제감속비 / 7
실제 감속비: hip 7 · thigh 7 · calf 10.5 · foot 8.4
gear_k:      hip 1.0 · thigh 1.0 · calf 1.5 · foot 1.2
```

정식 변환은 `q_raw = (q_ch − offset) / (sign · k)` 다. 그런데 브리지 구현은:

```cpp
// scripts/real2sim/r2s_biped_leg/real_runner/real_runner_bipedleg.cpp:73
float motor_deg_to_sim(int m, float pos_deg) {
    return MOTOR_CALIB[m].sign * (pos_deg - MOTOR_CALIB[m].zero_deg) * DEF_DEG2RAD;
}
```

`k` 로 나누는 항이 없다. `sign` 은 SignFix 로 자산에 흡수돼 전 축 +1 이 정답이고(RL_INTERFACE 의
−1 축 5개 = SignFix 반전 축 5개로 정확히 일치), `zero_deg` 는 아직 placeholder 0 이다
(RL_INTERFACE §3 에 실측 offset 이 이미 있다: HL_calf −66.62°, HL_foot −85.19° 등).

## 2. 무엇이 틀어졌나

우리가 "sim rad" 라고 부르며 다뤄 온 값 `u` 는 사실 **채널각**이다:

| 축 | 우리 값 `u` | 참값 | 오차 |
|---|---|---|---|
| hip, thigh | = 관절각 | | 없음 (k=1) |
| **calf** | = 관절각 × 1.5 | | **1.5배 과대** |
| **foot** | = raw각 × 1.2 | | **1.2배 과대** |

그리고 커플링 계수를 **채널각 공간에 적용**했다. `RL_INTERFACE.md` §2-(a) 가 정확히 이 함정을
경고한다:

> coef 는 raw각·모델각 공간(= 감속비 *이후*)의 계수다 — 채널각/모터축각 공간이 아니다.
> `k_foot/k_calf = 1.2/1.5 = 0.8`. … 채널각 공간으로 착각해 넣으면 30° vs 24° 로 어긋난다.

즉 우리 데이터가 사는 좌표에서 유효 커플링 계수는 **0.8** 이어야 하는데 **1.0** 을 썼다.

## 5. 살아남는 결론

**foot viscous 3.9 는 물리적으로 불가능하다** — `logs/torque_budget_check.py` 의 에너지 논증.
foot 단독 chirp 에서 모터가 낼 수 있는 파워의 5.1~5.4 배를 마찰로만 요구한다.

이 논증은 gear_k 오차에 대해 강건하다. **파워는 좌표 불변**이기 때문이다 — 채널 규약에서
`τ_ch = τ_motor·7`, `q̇_ch = ω_motor/7` 이라 곱이 보존되므로, 데이터에서 잰 공급 파워
0.45~2.36 W 는 배율과 무관한 참값이다. 소산 쪽 `b·q̇²` 도 적합이 쓴 것과 **같은 좌표**에서
계산했으므로 비교 자체가 성립한다.

다만 `b = 3.9` 자체는 각도만 채널 규약이고 관성·중력은 URDF 참값인 **혼성 모델**에서 나온
값이라 정확한 크기는 재적합 전까지 확정할 수 없다. 5.1~5.4 배라는 규모가 1 아래로 내려올
여지는 없지만, 배수는 재계산 대상이다.

## 6. 전치 토크(τ_calf += τ_foot) — **판정 불능이었음. 기본 True 로 복귀 (2026-08-14 정정)**

> ### 정정 요약
>
> 2026-08-13 에 아래 실측을 근거로 전치를 반증했다고 판단하고 `foot_transpose = False` 로 바꿨다.
> **틀렸다.** 2026-08-14 에 실기팀이 확인해 준 구조는:
>
> ```
> calf 모터 → 기어 → 무릎
> foot 모터 → 기어 → 무릎을 건너는 1:1 벨트 → 발목      (두 모터 모두 허벅지에 위치)
> ```
>
> 벨트가 무릎을 건너므로 foot 모터 출력각은 발의 **대퇴 기준** 각도 θ_f = q_foot + q_calf 다.
> 이건 **기구 구속**이고, 일률 보존에서 토크 관계가 강제된다 — 선택의 여지가 없다.
>
> 아래 실측이 전치를 반증하지 못하는 이유: **무릎 드라이브 정지마찰이 외란을 먹으면 동일한
> 결과**가 나온다. 필요한 정지마찰은 **4.87 / 4.80 N·m** 뿐이고, 이는 무릎 peak 토크 126 N·m 의
> **3.9%** 로 10.5:1 감속기에서 지극히 평범하다. 즉 반증이 아니라 **판정 불능**이었다.
>
> 당시 쓴 마찰 추정 1.1 N·m 은 (ⓐ gear_k 오염 적합에서 나왔고 (ⓑ calf 가 움직이는 chirp 구간의
> **운동마찰**이라, calf 가 정지해 있는 foot 단독 chirp 의 **정지마찰**에 적용할 값이 아니었다.
>
> **판정 가능한 검정**: calf 를 **천천히 등속으로 움직이면서**(이미 미끄러지는 중 = 정지마찰 없음)
> foot 을 chirp 한다. 그러면 외란이 무릎 추종오차·토크에 반드시 드러난다. 기존 캡처에는 이 조건이
> 없다 — 새로 받아야 한다.

무릎은 발목 토크에 **겉보기로는** 아무 반응도 하지 않는다. τ_ch2 는 평균 −1.17 N·m(중력 유지분)에
변동 std 가 0.027~0.041 N·m 뿐이다.

### 왜 이것이 반증이 못 되는가

이 검정이 재는 τ 는 PD 법칙 `kp(des−q) + kd(−q̇)` 로 계산한 **지령 토크**다. 외란을 **정지마찰이
흡수하면 관절이 움직이지 않고, 따라서 지령 토크도 변하지 않는다** — 검정이 그 경로에 눈이 멀어
있다. 외란이 마찰을 넘는 구간만 골라 봐도 결과는 같다:

| 축 | 최대 외란 \|0.8·τ_ch3\| | PD 가 낸 토크 | **필요한 정지마찰** | 무릎 peak 대비 |
|---|---|---|---|---|
| HL | 5.04 N·m | 0.16 N·m | **4.87 N·m** | 3.9% |
| HR | 4.84 N·m | 0.04 N·m | **4.80 N·m** | 3.8% |

10.5:1 감속기에서 peak 토크의 4% 짜리 정지마찰은 지극히 평범하다. 즉 이 데이터는
"전치 없음"과 "전치 있음 + 무릎 정지마찰 ≈4.9 N·m"를 **구분하지 못한다**.

`fit_bipedleg.py --foot_transpose on|off` 로 언제든 A/B 할 수 있다.

### ⚠ 아직 검정하지 않은 방향 — `τ_foot −= τ_calf`

위 실측이 반증한 것은 **foot → calf** 방향(`τ_calf += τ_foot`)뿐이다. 그 반대인
**calf → foot** (`τ_foot −= τ_calf`) 은 **한 번도 재지 않았다**. 전체 chirp 는 두 축이 동시에
움직여 교란돼 있고, foot 단독 chirp 는 calf 가 정지라 calf 토크 자체가 변하지 않는다.

이 조합("위치도 토크도 calf → foot 단방향, 역방향은 없음")은 사용자가 처음부터 일관되게
관찰해 온 단방향성과 정확히 맞는다. 기구 링키지라면 전치 관계가 강제되므로 이런 하삼각 토크
결합은 불가능하지만, **펌웨어 변환이면 가능하다** — 드라이버가 그렇게 짜여 있으면 된다.

- 검정: **calf 단독 chirp**(foot 정지 명령). `logs/transpose_evidence.py` 와 같은 방식으로
  회귀 τ_ch3/τ_ch2 를 본다. 계수가 0 이 아니면 이 방향은 실재한다.
- 코드로도 확인 가능: 실기팀 `deploy_hw.hpp:356-361` 에 토크 변환이 어떻게 적혀 있는지
  (하삼각인지 상삼각인지) 직접 읽으면 된다.

## 7. 실기팀 분석에서 추가로 나온, sim 에 없는 두 가지

**(a) 실현가능 토크 집합이 박스가 아니다.** 드라이브가 내는 토크는
`τ_drive_calf = τ_calf − τ_foot` (±126.0 N·m), `τ_drive_foot = τ_foot` (±100.8 N·m).
관절토크 공간의 허용영역은 독립 박스가 아니라 **전단된 평행사변형**이다. 부호가 반대면 무릎 여유가
줄고(τ_foot = −100.8 일 때 τ_calf 는 +25.2 까지), 같은 부호면 넓어진다(+226.8 까지).
현재 sim 은 관절별 `effort_limit` 박스라 **실기가 낼 수 없는 조합을 명령할 수 있다** — 보행 학습
전에 막아야 하는 sim2real 갭.

**(b) 관성 커플링(질량행렬 비대각항).** foot 로터는 관절각이 아니라 raw각으로 돌므로
`KE = ½·I_r·N²·(q̇_foot + q̇_calf)²` → 질량행렬에 `a·[[1,1],[1,1]]`, `a = I_r·N² = 7.4e-4 × 8.4² = 0.0522`.
현재 cfg 의 armature 초기치(calf 0.0816 = 7.4e-4×10.5², foot 0.0522 = 7.4e-4×8.4²)는 **대각항만**
맞다. Isaac 의 armature 는 DOF 별 스칼라라 **비대각항을 표현할 수단이 없다** — 구조적 한계.
이 항은 무토크에서도 살아 있어 "foot 을 움직이면 calf 가 반작용한다" 의 일부를 만든다.
