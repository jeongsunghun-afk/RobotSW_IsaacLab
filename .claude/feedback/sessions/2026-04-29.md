- **결과**: 성공 — PhysX 에러 해결 + 4종 신규 terrain (hurdle/step/gap/stair) IsaacLab 사용 가능

## 잘 된 것

### 1. PhysX Patch Buffer Overflow Fix
- **에러 분석**: `PhysX error: Patch buffer overflow detected, please increase its size to at least 536321`
- **원인 식별**: `parkour_env_cfg.py`의 `SimulationCfg`에 `physx=PhysxCfg(...)` 미지정 → 기본값 `gpu_max_rigid_patch_count = 5*2**15 = 163840` 사용. parkour 지형 (stairs/boxes/gaps/stepping_stones × 4096 envs)에서 contact patch가 폭증하여 overflow.
- **수정**: SimulationCfg에 `physx=PhysxCfg(gpu_max_rigid_patch_count=2**20, gpu_found_lost_pairs_capacity=2**22, gpu_total_aggregate_pairs_capacity=2**22)` 추가. patch_count는 요구치 536321 대비 약 1.95× 안전마진(1,048,576).
- cfg-worker 단독 위임 (작은 변경이라 full team pipeline 대신).

### 2. Genesis Parkour Terrain 4종 IsaacLab 포팅
- **Genesis 원본 분석**: `/home/lgb/RobotSW_Genesis/genesis/ext/isaacgym/terrain_utils.py`의 4개 함수 (parkour_hurdle/step/gap/stair_terrain) 직접 읽어 의미 파악. heightfield 기반(2D grid에 height 채우는 방식)이라 IsaacLab의 trimesh 기반과 패러다임이 다름.
- **포팅 전략**: heightfield → trimesh.box로 변환. corridor 구조(좌/우 두 박스 + 가운데 통로)로 hurdle/step의 통로 구현. gap은 ground plane 미생성으로 실제 추락 의미 보존.
- **추가 결과**:
  - `MeshParkourGapTerrainCfg / parkour_gap_terrain` — 시작 platform → N개 gap + 중간 platform → end platform. ground 없음.
  - `MeshParkourHurdleTerrainCfg / parkour_hurdle_terrain` — 좌/우 박스 + 통로 구조. flat 옵션으로 비활성 가능.
  - `MeshParkourStairTerrainCfg / parkour_stair_terrain` — 직선형 오름→평지→내림→평지 사이클 N회 반복.
  - `MeshParkourStepTerrainCfg / parkour_step_terrain` — corridor 내 피라미드 step 시퀀스.
- difficulty 기반 보간(hurdle_height_range, gap_length_range 등)으로 IsaacLab 표준 curriculum과 호환.

### 3. 검증
- 각 cfg 클래스: `@configclass` + `function = mesh_terrains.xxx_terrain` 패턴 일치
- 각 함수: `(difficulty: float, cfg) -> tuple[list[Trimesh], np.ndarray]` 시그니처 준수
- `__init__.py` export 알파벳순 유지
- `dim_z > 1e-3` 가드로 zero-dim box 회피
- pyright 신규 에러 0건 (기존 IsaacLab MISSING sentinel 패턴 그대로 따름)

## 분석 / 인사이트

### PhysX GPU Buffer 사이징 원칙
- Isaac Sim 기본값은 GPU rigid patch buffer가 작아서 (5 × 2^15 = 163,840) 복잡 mesh terrain × 4096+ envs 환경에서 즉시 overflow 발생.
- parkour처럼 stairs/boxes/stepping_stones/gaps 등 다양한 mesh가 동시 활성화되는 경우, 필요한 patch_count를 미리 추정 어려움 → 안전마진 2× 이상 잡는 게 합리적.
- `gpu_max_rigid_patch_count` 외에 `gpu_found_lost_pairs_capacity`, `gpu_total_aggregate_pairs_capacity`도 함께 상향하는 게 broadphase 안정성에 유리 (R_Skeleton_amp 패턴과 동일).
- **트리거 조건**: num_envs ≥ 4096 + 복잡 mesh terrain (TerrainImporter + 다양한 sub-terrain) 사용 시 PhysxCfg 명시 상향 필수.

### Heightfield → Trimesh 포팅 핵심 변환
| Genesis (heightfield) | IsaacLab (trimesh) |
|----------------------|---------------------|
| 2D grid에 height 값 채우기 | trimesh.box를 위치/크기로 직접 배치 |
| 가운데 통로 = grid 셀에서 0 유지 | 좌측 박스 + 우측 박스 두 개로 통로 표현 |
| gap = negative height (아래로 패임) | gap = box 미배치 (ground plane 없으면 실제 추락) |
| 경계 padding | `make_border` util 호출 |
| 가산식 height 누적 | 각 단계마다 box 1개 (높이 = 누적값) |

### Genesis의 Parkour Terrain 5종 vs IsaacLab 매핑
- Genesis: `parkour_flat`, `parkour_hurdle`, `parkour_step`, `parkour_gap`, `parkour_stair`
- `parkour_flat`은 사실 `parkour_hurdle_terrain(flat=True)` (Genesis 코드에서 동일 함수 호출). IsaacLab 포팅에서도 `MeshParkourHurdleTerrainCfg(flat=True)`로 동일하게 표현 가능. 별도 cfg 불필요.
- 따라서 4종(gap/hurdle/stair/step) 포팅으로 5종 모두 커버.

### 작업 분배 결정
- 단일 worker (executor)에 두 파일 동시 수정 위임 → race 회피 + 일관된 패턴 유지
- 단순 한 줄 cfg 변경(작업 1)은 cfg-worker 단독, 신규 모듈 추가(작업 2)는 executor가 적합. full team pipeline (plan→prd→exec→verify→fix)은 작업 규모에 비해 과한 오버헤드라 우회.
