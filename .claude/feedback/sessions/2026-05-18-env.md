# [2026-05-18] Isaac Sim 다중 버전 관리 — 환경변수 충돌 해소 및 버전 스위처 구현

## 작업 요약

- **목적**: Isaac Sim 3개 버전(5.1 소스빌드 / 4.5 pip / 6.0 소스빌드) 병행 사용 환경에서 `ISAACSIM_PATH` 하드코딩으로 인한 stale 경로 문제 해결
- **결과**: 성공. `~/.bashrc`에 `use_isaac {5|4.5|6}` 버전 스위처 함수 추가 완료. 각 버전의 conda env + 환경변수 + IsaacLab 심링크를 한 번에 전환. 3개 버전 전환 검증 완료.

## 잘 된 것

- 버전별 설치 구조 차이 진단 성공 — 5.1·6.0은 소스빌드(`_build/linux-x86_64/release` 하위), 4.5는 pip 설치(`python.sh` 부재)
- `use_isaac 4.5` 실행 시 `ISAACSIM_PATH`/`ISAACSIM_PYTHON_EXE`를 `unset` 처리하여 pip 설치판 특성 반영
- IsaacLab `_isaac_sim` 심링크 자동 재지정으로 Isaac Sim ↔ IsaacLab 버전 커플링 관리
- `bash -ic`로 `.bashrc` source 후 검증 — `use_isaac 5/4.5/6` 실행 시 `CONDA_DEFAULT_ENV`가 각각 `isaac`/`isaac-4.5`/`isaac-6.0`로 전환, `ISAACSIM_PATH`는 5·6에서 설정·4.5에서 unset 확인

## 잘 안 된 것

### 1차 초안의 설계 오류 — 사용자 지적으로 발견

- **문제**: `use_isaac` 함수 1차 초안에서 4.5를 standalone 디렉토리 `/home/lgb/IsaacSim-4.5` 기반으로 설계했고, conda 환경 전환 로직(`conda activate`)이 빠져 있었음 (`ISAACSIM_PATH`만 설정).
- **발견 계기**: 검증 실패가 아니라 **사용자의 지적**. 사용자가 "4.5는 standalone이 아니라 pip로 설치해서 쓰고 있다"고 알려줌. 1차 초안은 그 시점 설계 가정(4.5 = standalone) 기준으로는 `ISAACSIM_PATH`·`python.sh`·심링크가 모두 정상 동작했음.
- **해결**: 환경을 재조사하여 conda env `isaac-4.5`에 pip `isaacsim==4.5.0.0`이 설치되어 있음을 확인 → 함수를 2차 수정. conda activate 추가, 4.5는 `ISAACSIM_PATH` unset 처리.

## 분석 / 인사이트

### Isaac Sim 설치 방식별 차이

| 버전 | 설치 방식 | conda env | 실행 스크립트 | ISAACSIM_PATH 필요 |
| --- | --- | --- | --- | --- |
| 5.1.0-rc.19+main | 소스 빌드 | `isaac` | `${ISAACSIM_PATH}/isaac-sim.sh` | 필요 |
| 4.5.0-rc.36 | pip (`isaacsim==4.5.0.0`) | `isaac-4.5` | `isaacsim` 콘솔 스크립트 | 불필요 |
| 6.0.0-rc.22+develop | 소스 빌드 | `isaac-6.0` | `${ISAACSIM_PATH}/isaac-sim.sh` | 필요 |

### pip 설치판(4.5) 검증 절차 차이

Isaac Lab/Sim 공식 docs는 소스/바이너리 설치를 가정하여 `${ISAACSIM_PYTHON_EXE} -c "..."`, `${ISAACSIM_PATH}/isaac-sim.sh`, `add_cubes.py` 검증을 안내한다. 그러나 pip 설치판은:

- `ISAACSIM_PATH`, `ISAACSIM_PYTHON_EXE` 개념 없음 — 패키지가 `site-packages/isaacsim`에 위치, 자동 resolve.
- `python.sh` 래퍼 없음 → conda env의 `python` 직접 사용.
- `isaacsim` 콘솔 스크립트(env `bin/`)가 GUI 엔트리포인트.

`/home/user/miniconda3/envs/isaac-4.5/` site-packages에 `isaacsim` 패키지와 20여 개 `isaacsim_*` 컴포넌트(core, gui, kernel, replicator, rl, robot, sensor 등) 확인. `/home/lgb/IsaacSim-4.5/` standalone 디렉토리는 별개 미사용 설치본. **pip 설치본 검증은 `python -c "from isaacsim import SimulationApp"` 및 `isaacsim` 명령 권장.**

### IsaacLab ↔ Isaac Sim 버전 커플링

IsaacLab은 `_isaac_sim` 심링크로 단일 Isaac Sim 버전에 바인딩된다. `use_isaac`는 5·6 전환 시 심링크를 자동 재지정하지만, IsaacLab 소스가 특정 Isaac Sim API에 의존할 경우 버전 전환 시 호환성 문제가 발생할 수 있다.

- **권장**: IsaacLab 클론을 버전별로 분리(예: `IsaacLab-5.1`, `IsaacLab-6.0`). 단일 클론을 5.1·6.0에 돌려쓰면 API breaking change로 런타임 오류 위험.

### conda `activate.d/clean_isaac_env.sh` 연동

`use_isaac 4.5`는 `conda activate isaac-4.5`를 거치므로, 기존 메모리(`isaacsim-pythonpath-pollution.md`)에 기록된 `activate.d/clean_isaac_env.sh`가 자동 실행되어 `PYTHONPATH` 정리가 적용된다 → 별도 수동 정리 불필요.
