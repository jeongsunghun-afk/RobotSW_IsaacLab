## 발견된 차이점 (Top-3 Root Cause)

### H1 — Reward 비대칭 (수직 속도 페널티 약화 + reward clip) — 신뢰도 **HIGH**

**무엇을**: A는 장애물 지형에서 수직 속도 페널티를 B 대비 5배 약하게 적용하고, 모든 음수 보상을 0으로 clipping.

**어디서**:
- `source/isaaclab_tasks/isaaclab_tasks/direct/parkour/parkour_env.py:1001` — `lin_vel_z_l2 *= (is_flat + is_non_flat * 0.1)`
- `source/isaaclab_tasks/isaaclab_tasks/direct/parkour/parkour_env.py:1108` — `torch.clip(total_reward, min=0.)`

**B 대비**:
- B는 `0.5` multiplier 사용 (`parkour_isaaclab/envs/mdp/rewards.py:144`)
- B는 reward clip 없음 (raw sum) ← **사용자 정정**: B에도 clip 존재 (`parkour_reward_manager.py:38`). **A/B 공통 의도된 설계**로 확인되어 H1에서 reward_clip 부분은 제외.

**왜**: 수직 속도 `v_z ≈ 2 m/s` 점프 시 step당 비용:
- A non-flat: `−1.0 × 0.02 × 0.1 × 4 = −0.008`
- B non-flat: `−1.0 × 0.02 × 0.5 × 4 = −0.040` (5배)

10~15 step 점프 사이클에서 A는 ~0.1 보상 손실, B는 ~0.5~0.7 손실. A는 `tracking_goal_vel = +1.5` 보너스로 충분히 상쇄 가능 → 점프가 경제적.

**검증 테스트 (T1)**: `parkour_env.py:1001`의 `0.1` → `0.5` 변경 후 학습.

```python
# before
lin_vel_z_l2 = lin_vel_z_l2 * (is_flat + is_non_flat * 0.1)

# after
lin_vel_z_l2 = lin_vel_z_l2 * (is_flat + is_non_flat * 0.5)
```

### H2 — Terrain 비율 불균형 (flat 10% / gap 30%) — 신뢰도 **HIGH**

**무엇을**: A는 순수 보행 학습 타일(flat)을 10%만 할당하고 gap(점프 필수) 타일을 30% 할당. B는 각각 20%/20%.

**어디서**: `source/isaaclab_tasks/isaaclab_tasks/direct/parkour/parkour_env_cfg.py:54-132`

| Terrain | A proportion | B proportion |
|---------|--------------|--------------|
| flat (보행 전용) | **0.10** | **0.20** |
| hurdle | 0.20 | 0.20 |
| step | 0.20 | 0.20 |
| gap | **0.30** | **0.20** |
| stair / extreme_parkour | 0.20 / 0 | 0 / 0.20 |

**왜**: A의 90% 타일이 장애물 포함. 보행 gradient를 받는 환경 샘플이 10%뿐 → PPO policy gradient가 "점프"로 편향. Gap은 width > 30cm 시 보행 불가능하므로 점프 필수 전략 강화.

**검증 테스트 (T2)**: 5개 타일 비율을 균등하게 0.20으로 변경.

```python
# parkour_env_cfg.py:54-132
# before
parkour_flat.proportion = 0.10
parkour_gap.proportion = 0.30

# after
parkour_flat.proportion = 0.20
parkour_gap.proportion = 0.20
```

### H3 — Reset 시 joint-pos noise 없음 — 신뢰도 **MEDIUM-HIGH**

**무엇을**: A는 모든 episode reset 시 4096 envs가 동일한 관절 자세로 시작. B는 관절별 ±5% multiplicative noise 적용.

**어디서**: `source/isaaclab_tasks/isaaclab_tasks/direct/parkour/parkour_env.py:1182`

```python
# A (current)
joint_pos = self._robot.data.default_joint_pos[env_ids]  # noise 없음

# B (Isaaclab_Parkour)
# parkour_mdp_cfg.py:267-274
# reset_joints_by_scale with position_range=(0.95, 1.05)
```

**왜**: 모든 env가 동일 upright 자세(.1/-.1 hip, .8/1.0 thigh, -1.5 calf)에서 시작 → exploration entropy = 0. 점프는 upright 자세에서 발견하기 쉬운 "다리 신전" 패턴. 보행은 half-crouch 등 다양한 초기 자세 탐색 필요하나 A는 해당 basin을 샘플링하지 않음.

**검증 테스트 (T3)**: ±5% joint-pos noise 추가.

```python
# parkour_env.py:1182
joint_pos = self._robot.data.default_joint_pos[env_ids].clone()
joint_pos *= 1.0 + (torch.rand_like(joint_pos) * 0.1 - 0.05)
```

## 분석 / 인사이트

### Multi-axis compound failure mode

A의 점프 전략 학습은 단일 원인이 아닌 3개 축의 복합 실패:

1. **Reward asymmetry** (H1) — 점프 비용을 5배 저렴하게 만듦
2. **Terrain imbalance** (H2) — 점프 필수 타일을 3배 과다 샘플링
3. **Exploration vacuum** (H3) — 동일 초기 자세로 보행 발견 경로 차단

각 요인 단독으로는 minor하나, 3개가 동시 작용 시 점프 고착(lock-in) 발생.

### Worker false-positive 메커니즘

Worker-1이 "B에 reward_clip 없음"을 확정 diff로 보고한 이유:
- A codebase(`parkour_env.py`)는 전체 정독, B codebase는 `rewards.py` 함수만 grep
- Manager-based B는 `RewardManager` wrapper가 clip 적용 → 함수 내부에 없음
- 단일 search miss로 false negative 발생

→ Memory `feedback_worker_absence_claim_must_verify.md`에 재발 방지 규칙 추가.

### Verification strategy design

T1~T5는 각각 1~2줄 변경으로 단일 변수 테스트:
- **T1 (highest leverage)**: 5배 차이 → 가장 큰 효과 예상
- **T2 (config-only)**: 코드 미수정, 비율만 변경 → 안전
- **T3 (low risk)**: 초기 termination 5~10% 증가 가능하나 회복 가능
- **T4 (integration)**: T1+T2+T3 동시 적용으로 compound effect 확인
- **T5 (fallback)**: T4로 해결 안 될 시 Axis 3 원인 탐색
