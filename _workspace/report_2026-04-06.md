## 원인 분석

### 이론적 배경: LCP Gradient Penalty의 목적

LCP는 다음 수식을 최소화하여 정책을 observation 변화에 robust하게 만든다:

```
L_GP = E[ ||∂ log π(a|o) / ∂o||² ]
```

즉, raw observation이 조금 바뀌어도 action 분포가 크게 바뀌지 않도록 Lipschitz-smooth 조건을 부여하는 것이 목적이다.

---

### 버그 1 (Critical): `priv_latent`를 독립 변수로 취급

**버그 코드** (`ppo_parkour.py:347` 수정 전):
```python
obs_est_for_lcp = torch.cat([obs_actor_lcp, priv_latent_lcp], dim=-1).requires_grad_(True)
```

`[o_norm, z]` 전체에 `requires_grad_(True)`를 설정하면 gradient가 다음처럼 계산된다:

```
∂log π / ∂[o_norm, z] = [ ∂log π/∂o_norm,   ← actor obs 부분
                           ∂log π/∂z        ] ← priv_latent 부분 (독립 변수 취급!)
```

**올바른 참조 구현** (`ppo_rma.py`):
```python
obs_est_batch = obs_batch.clone()
obs_est_batch.requires_grad_()          # raw obs 전체가 leaf
self.actor_critic.act(obs_est_batch)    # act() 내부에서 z = f(obs_batch) 계산
```

참조에서는 `o_raw`를 leaf variable로 두면 chain rule에 의해:

```
∂log π / ∂o_raw = (∂log π/∂o_norm)(∂o_norm/∂o_raw)    ← actor obs 경로
                + (∂log π/∂z)(∂z/∂o_raw)                ← priv_encoder 경로 (o_raw의 함수)
```

`z`가 `o_raw`의 함수로 취급되므로, `z 자체의 sensitivity`가 아니라 `o_raw 변화가 z를 통해 policy에 미치는 영향`이 측정된다.

**영향**: `∂log π/∂z`를 직접 penalize하면 actor가 priv_latent를 무시하도록 학습된다. priv_latent는 terrain/friction 등 환경 적응 정보를 담고 있으므로, 이를 무시하면 task reward 저하가 발생한다.

---

### 버그 2 (Critical): Gradient Penalty 발산 + Entropy 증가 메커니즘

`[o_norm, z]`를 독립 변수로 취급하면 gradient penalty가 원래보다 더 많은 차원(z 차원 추가)을 합산하므로 값 자체가 크다.

정책 입장에서 L_GP를 줄이는 가장 쉬운 경로:

```
L_GP = E[ ||(a - μ)/σ² * ∂μ/∂obs||² ]  (state-independent σ 가정)
     ∝ 1/σ² * ||∂μ/∂obs||²
```

→ **σ를 키우면 L_GP가 작아진다** → 그런데 entropy = `Σ log(σ)` 이므로 σ 증가 = entropy 증가

이것이 "gradient penalty 발산과 entropy 증가가 동시에 나타나는" 패턴의 수학적 원인이다. 정책은 학습을 통해 sigma를 키워 penalty를 회피하고, 결과적으로 action이 무작위화된다.

---

### 버그 3 (Minor): Normalized obs를 leaf variable로 사용

**버그 코드**:
```python
obs_actor_lcp = self.policy.actor_obs_normalizer(obs_actor_lcp)   # 정규화 후
obs_est_for_lcp = torch.cat([obs_actor_lcp, ...]).requires_grad_(True)  # 정규화 이후가 leaf
```

normalizer를 통과한 후에 leaf를 설정하면, gradient는 `o_norm` 공간에서 계산되고 normalizer의 scale이 반영되지 않는다. 원래 의도는 `o_raw` 공간에서의 sensitivity를 regularize하는 것이므로 설계 의도와 다르다.

---

### 버그 4 (Additional): scandot_latent 누락

`_update_distribution(cat_obs)`를 직접 호출할 때 `scandot_encoder`가 있는 경우 scandot_latent가 포함되지 않으면 차원 불일치가 발생할 수 있다.

## 수정 내용

**파일**: `rsl_rl/rsl_rl/algorithms/ppo_parkour.py` :342~359

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| leaf variable | `cat([o_norm, z]).requires_grad_()` | `o_raw.detach().requires_grad_()` |
| gradient 공간 | `[o_norm, z]` 공간 (z가 독립 변수) | `o_raw` 공간 (z는 상수) |
| normalizer | gradient 끊긴 채 통과 | gradient 유지하며 통과 |
| priv_latent | 독립 변수로 penalize | `no_grad` 상수 취급 |
| scandot_latent | 누락 | `no_grad` 상수로 포함 |

**수정 후 코드** (핵심 부분):
```python
# raw obs에 requires_grad 설정 (정규화 이전 — normalizer chain rule 적용됨)
obs_actor_raw_lcp = self.policy.get_actor_obs(obs_batch).detach().requires_grad_(True)
obs_actor_norm_lcp = self.policy.actor_obs_normalizer(obs_actor_raw_lcp)  # gradient 유지

with torch.no_grad():
    priv_latent_lcp = self.policy.get_priv_latent(obs_batch)  # z는 상수 취급

cat_obs_lcp = torch.cat([obs_actor_norm_lcp, priv_latent_lcp], dim=-1)
# (scandot 있으면 no_grad로 추가)

self.policy._update_distribution(cat_obs_lcp)
actions_log_prob_for_lcp = self.policy.get_actions_log_prob(...)
grad_log_prob = torch.autograd.grad(
    actions_log_prob_for_lcp.sum(), obs_actor_raw_lcp, create_graph=True  # ← o_raw에 대해 미분
)[0]
gradient_penalty_loss = torch.sum(torch.square(grad_log_prob), dim=-1).mean()
```

## 분석 / 인사이트

1. **`requires_grad_()`의 위치가 gradient 의미를 결정한다.** leaf variable을 어디에 설정하느냐에 따라 "어떤 공간에서의 sensitivity"를 측정하는지가 완전히 달라진다. `[o_norm, z]`에 설정하면 z를 독립 변수로 취급하게 되어 원래 의도와 전혀 다른 regularization이 된다.

2. **entropy 증가는 gradient penalty가 잘못 적용되었다는 간접 증거다.** 정책이 entropy를 키워 gradient penalty를 회피하는 패턴은, penalty 항이 정책의 "올바른" 학습 방향과 충돌하고 있음을 시사한다.

3. **참조 구현과 flat tensor vs TensorDict 구조 차이가 이식 오류를 유발했다.** 원 구현은 `obs_batch`가 flat tensor라서 `requires_grad_()`를 직접 걸 수 있었지만, 현재 구조는 TensorDict이므로 직접 적용이 불가능하다. 이 구조적 차이를 인식하지 못하면 동일해 보이는 코드가 완전히 다른 의미를 가질 수 있다.
