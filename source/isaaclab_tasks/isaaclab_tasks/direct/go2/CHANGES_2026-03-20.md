## 개요

Go2 Interaction 강화학습 환경에서 발견된 3가지 문제를 수정하였다.

1. Base frame 보상 및 시각화 좌표 변환 버그
2. Stand 커맨드의 명확한 목표 자세 미정의
3. Stand 자세 유지 중 앞다리 떨림 현상

---

## 수정 1 — Base Frame 보상 · 시각화 버그 수정

### 문제

`reward_frame = "base"` 설정 시 보상 계산과 디버그 시각화 모두에서 좌표 변환 오류가 존재하였다.

CSV에서 불러온 `hip_local` / `foot_local` 값은 이미 **로봇 body frame 기준 상대 오프셋**임에도 불구하고, 참조 자세의 쿼터니언(`ref_quat`)으로 역회전을 한 번 더 적용하고 있었다.

```
[잘못된 변환 흐름]
hip_local (body frame 오프셋)
  → quat_apply_inverse(ref_quat, hip_local)   ← 불필요한 회전
  → 보상 계산 / 시각화에 사용

결과: 실제 추적 대상 위치와 시각화 마커 위치가 모두 틀린 값을 가리킴
```

### 수정 내용

**`_get_rewards()` — 보상 계산**

```python
# 수정 전
ref_quat     = quat_from_euler_xyz(ref_rot[:, 0], ref_rot[:, 1], ref_rot[:, 2])
ref_quat_rep = ref_quat.unsqueeze(1).repeat(1, 4, 1)
target_hip_local  = quat_apply_inverse(ref_quat_rep, hip_local)   # ← 잘못된 회전
target_foot_local = quat_apply_inverse(ref_quat_rep, foot_local)

# 수정 후
target_hip_local  = self._target_reference_positions["hip_local"]   # 그대로 사용
target_foot_local = self._target_reference_positions["foot_local"]
```

**`_calculate_reference_positions()` — 시각화**

```python
# 수정 전 (ref_quat 역회전 후 robot quat 적용 → 이중 변환)
target_hip_in_ref_body  = quat_apply_inverse(ref_quat_rep, hip_local)
vis_hip_world  = root_pos_w + quat_apply(root_quat_rep, target_hip_in_ref_body)

# 수정 후 (현재 로봇 회전만 적용)
vis_hip_world  = root_pos_w.unsqueeze(1) + quat_apply(root_quat_rep, hip_local)
vis_foot_world = root_pos_w.unsqueeze(1) + quat_apply(root_quat_rep, foot_local)
```

### 결과

시각화 마커가 "현재 로봇 위치와 자세를 기준으로 body frame 타겟이 world 어디에 해당하는지"를 올바르게 표시하게 되었으며, 보상 계산도 동일한 논리로 정확하게 동작한다.

## 수정 2 — Stand 커맨드 목표 자세 정의

### 문제

Stand 커맨드(cmd = 3)는 `stand_cap_v2.csv`의 프레임을 처음부터 끝까지 순환(`frame % motion_length`)하도록 구현되어 있었다. 이로 인해 **안정적인 기립 자세(뒷발 지지 + 앞발 들기)에 대한 고정 타겟이 존재하지 않았으며**, 정책이 명확한 목표 없이 학습되는 문제가 있었다.

**Stand 커맨드의 목표 정의**
- 뒷다리(RL, RR)로 지면을 딛고 안정적으로 지지
- 앞다리(FL, FR)를 들어 올려 기립 자세 유지

### 수정 내용

클래스 수준 상수로 body-frame 기립 자세 타겟을 정의하고, `_calculate_reference_positions()` 내부에서 cmd == 3 환경에 덮어쓰도록 구현하였다.

**추가된 클래스 상수** (`go2_interaction_env.py`)

```python
# 순서: FL, FR, RL, RR  /  축: x = 전후, y = 좌우, z = 상하
STAND_HIP_LOCAL = [
    [ 0.18,  0.07,  0.03],   # FL hip
    [ 0.18, -0.07,  0.03],   # FR hip
    [-0.18,  0.07, -0.03],   # RL hip
    [-0.18, -0.07, -0.03],   # RR hip
]
STAND_FOOT_LOCAL = [
    [ 0.15,  0.09,  0.28],   # FL foot — 들어올림
    [ 0.15, -0.09,  0.28],   # FR foot — 들어올림
    [-0.10,  0.09, -0.48],   # RL foot — 지면 지지
    [-0.10, -0.09, -0.48],   # RR foot — 지면 지지
]
STAND_BASE_HEIGHT = 0.65   # 기립 시 base 높이 (m)
STAND_BASE_PITCH  = 1.1    # 기립 시 pitch (rad, 약 63도)
```

**`_calculate_reference_positions()` 내 오버라이드 로직**

```python
mask_stand = (self._interaction_command.squeeze(-1) == 3)
if mask_stand.any():
    n_stand    = int(mask_stand.sum().item())
    stand_hip  = torch.tensor(self.STAND_HIP_LOCAL,  ...).unsqueeze(0).expand(n_stand, -1, -1)
    stand_foot = torch.tensor(self.STAND_FOOT_LOCAL, ...).unsqueeze(0).expand(n_stand, -1, -1)

    ref["hip_positions_local"][mask_stand]  = stand_hip
    ref["foot_positions_local"][mask_stand] = stand_foot
    ref["base_height"][mask_stand]          = self.STAND_BASE_HEIGHT
    ref["base_rotation"][mask_stand, 1]     = self.STAND_BASE_PITCH

    root_pos_stand = self._robot.data.root_link_pos_w[mask_stand].unsqueeze(1)
    ref["hip_positions"][mask_stand]  = root_pos_stand + stand_hip
    ref["foot_positions"][mask_stand] = root_pos_stand + stand_foot
```

### 결과

Stand 커맨드 환경은 CSV 모션 순환 대신, 매 스텝 동일한 기립 자세 타겟을 추적하게 되었다. 기존 코드에서 Stand 시 height/pitch 보상에 이미 2배 가중치가 적용되어 있어, 새 타겟과 함께 기립 방향으로의 학습이 강화된다.

## 수정 3 — Stand 앞다리 떨림 억제

### 문제

기립 자세에서 앞발이 목표 위치 근처에 도달한 후에도 지속적으로 진동하는 현상이 관찰되었다. 기존에 `action_rate`, `dof_acc` 패널티가 존재함에도 발생하는 이유는 다음 세 가지다.

| 원인 | 내용 |
| --- | --- |
| 보상 함수 기울기 | `exp(-e/σ)`는 타겟 근처에서도 강한 기울기를 가짐 → 작은 오차에도 과잉 보정 발생 |
| 패널티 규모 불균형 | `action_rate` 패널티가 위치 추적 보상의 약 1/100 수준 → 정책이 떨림을 감수하고 타겟 추적 선택 |
| Stand 특화 규제 없음 | 기존 패널티는 12관절 전체 / 모든 커맨드에 동일 적용 → 앞다리 진동을 선별적으로 억제하지 못함 |

### 수정 내용

**`__init__()` — 앞다리 관절 인덱스 추가**

```python
front_names = ["FL_hip", "FL_thigh", "FL_calf", "FR_hip", "FR_thigh", "FR_calf"]
self._front_joint_ids = torch.tensor(
    [i for i, n in enumerate(all_joint_names) if any(fn in n for fn in front_names)],
    dtype=torch.long, device=self.device,
)
```

**보상 A — Stand 앞다리 관절 속도 패널티**

cmd == 3인 환경에만 적용. FL/FR 6개 관절 속도의 제곱합을 패널티로 부과한다.

```python
rew_stand_front_vel = torch.zeros(self.num_envs, device=self.device)
if mask_stand.any():
    front_vel_sq = torch.sum(
        torch.square(self._robot.data.joint_vel[:, self._front_joint_ids]), dim=1
    )
    rew_stand_front_vel[mask_stand] = front_vel_sq[mask_stand]
```

**보상 B — 앞발 근방 정지 보상**

FL/FR 발이 타겟 8cm 이내에 진입한 경우에만 활성화. 관절 속도가 낮을수록 높은 보상을 부여하여 타겟 도달 후 안정 유지를 유도한다.

```python
rew_front_stillness = torch.zeros(self.num_envs, device=self.device)
if mask_stand.any():
    front_near = (foot_pos_error[:, 0] < 0.08) & (foot_pos_error[:, 1] < 0.08)
    active = mask_stand & front_near
    if active.any():
        front_vel_mag = torch.norm(
            self._robot.data.joint_vel[:, self._front_joint_ids], dim=1
        )
        rew_front_stillness[active] = torch.exp(-front_vel_mag[active] / 0.5)
```

**`go2_interaction_cfg.py` — 스케일 파라미터 추가**

```python
stand_front_vel_reward_scale: float = -0.05   # 보상 A — 속도 패널티 (음수)
front_stillness_reward_scale: float =  0.5    # 보상 B — 정지 보상 (양수)
```

### 두 보상의 역할 분담

| 보상 | 활성 구간 | 역할 |
| --- | --- | --- |
| `stand_front_vel` (A) | cmd = 3 전체 | 앞다리의 빠른 움직임을 전반적으로 억제 |
| `front_stillness` (B) | 타겟 8cm 이내 도달 후 | 타겟 도달 이후 진동 없이 자세 유지 강제 |

### 스케일 조정 가이드

```python
# 떨림이 여전히 심한 경우 → A 강화
stand_front_vel_reward_scale: float = -0.1

# 자세 진입 자체가 너무 느려진 경우 → A 약화, B 강화
stand_front_vel_reward_scale: float = -0.02
front_stillness_reward_scale: float =  1.0
```
